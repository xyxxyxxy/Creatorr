# Download pipeline and library file lifecycle

Index: [README.md](README.md). Terminology: [`domain-model.md`](domain-model.md) (via [`AGENTS.md`](../AGENTS.md)).

## Download pipeline

1. Resolve / download via **in-tree yt-dlp** (`internal/ytdlp`) into a temp work dir. When the series has `auto_ignore_media_types`, Creatorr passes `--match-filters` (`media_type!=…` joined with `&`). yt-dlp writes **media + sidecars** (`info.json`, thumbnail, and subtitle files when Library subtitle languages are set) in one extract when possible (optional plugins under `/yt-dlp-plugins` or `var/yt-dlp-plugins`). Download task progress follows yt-dlp’s reported percent (0–1). On success, video history **`downloaded`**.
2. When the quality profile has **SponsorBlock remove** categories: stage media+sidecars under `{CacheDir}/sponsorblock-cut/{videoID}/`, enqueue system-lane **`sponsorblock_cut`** (low priority), finish the download task (`downloaded` message notes staged for cut). Video stays **`wanted`** until cut packs. No remux in the download task on this path (reencode already writes MKV; copy-cut remuxes inside the cut task).
3. When remove is empty: **Remux** via Creatorr ffmpeg to MKV when the file extension is not already `.mkv` (`library.RemuxIfNeeded`). History event `remuxed` only when remux ran. Then **SponsorBlock** mark/chapter embed in the same download task when mark is set (or creator chapters only).
4. **`sponsorblock_cut`** (system): fetch segments; cut (copy or reencode); optional hard-cut info cards (~2s) when reencode + cards; remap chapters/subs; pack. Soft-fail warns on the task. History **`sponsorblock_cut`** when a cut applied. Re-encode cut reports numeric progress for keep-segment ffmpeg and for filter-stitch when cards force a re-encode join (0–1, weighted across both passes); remux, info cards, pack, and copy-cut are message + spinner. On Linux, re-encode ffmpeg (keeps + info cards + filter stitch) runs at fixed nice 10 (not a CPU %; no Settings key); non-Linux is unchanged. Never yt-dlp `--sponsorblock-*` / `--embed-chapters`. Persist `.sponsorblock.json` beside packed media when cuts applied. Cancel deletes staging (same recovery as cancel download: re-download later).
5. **Pack** under the library root: the **video** becomes an on-disk **episode** (`library.PackMedia` / `BuildEpisodePaths`: always under `SeriesDir`, then relative path from Settings `episode_format`, full episode NFO via `WriteEpisodeNFO`, optional info.json + thumb + **subtitle sidecars** with language in the filename, e.g. `.en.srt` or `.en.auto.srt` for auto-only). Default layout nests `S{year}/…` under the series folder. Missing `upload_date` leaves season/episode unset in the index; pack and stream pack use year-season **0**, so `{year}` expands to **`0000`** (e.g. `S0000/…`), not TV default `S1`. Saving the format does **not** rename existing files - use **Apply episode format** (Settings → Library → Maintenance). Successful Apply writes video history `renamed` (previous/new name). See **Episode** in [`domain-model.md`](domain-model.md). Soft-fill `videos.media_type` from packed info.json when present.
6. Write Creatorr-owned columns on video (`CompleteDownload` → `tool` / `download_format_selector` / `download_remux_container` only when remuxed / duration+resolution from info.json → history **`packed`**; sets `acquired_at` and `sidecars_acquired_at`). Creatorr does **not** run a separate sidecars / metadata rescan after download. Packed **`info.json` is download-time provenance**: write/replace only when the media file changes (archive download or maturity re-download). Creatorr **never edits `info.json` content** (copy/move only). Subtitles are **never embedded** in the media file (keeps refresh via metadata rescan / Refresh sidecars / maturity sidecar refresh).
7. **Media verify (optional):** when the quality profile has **`verify_media`**, after a successful archive pack Creatorr may enqueue system-lane **`media_verify`** (lowest priority, below `sponsorblock_cut`). Null-decode only (`ffmpeg -xerror -i … -f null -` with `-progress`). **Mature-only** when `maturity_redownload_hours` > 0: skip young first packs; verify on maturity re-download and when maturity will never run. Hours = 0 verifies every archive pack. Success → history **`verified`** (status stays `downloaded`). Fail → **keep files**, status **`verify_failed`**, history + Apprise **`verify_failed`**, task `MediaVerifyFailed`. Does **not** count toward `source_download_error_threshold`. Cancel leaves `downloaded`. New pack cancels prior verify for that video (superseded ≠ verify_failed). Import confirm checkbox **`verify`** always enqueues (ignores mature gate). Accepted: Emby may play before verify finishes or after `verify_failed`.
8. On **auto-ignore media type** reject (`MediaTypeExcluded`): finished download task is **`done`** (not failed); video → **`ignored`** (reason `media_type`); no `ytdlp_failed` notify; no source-error threshold bump. **Download now** still enforces the filter when type is known and listed. On other failure: finished download task in History (`failed`); video status **`wanted_download_error`** with history detail `stage` (`fetch` / `remux` / `pack`) and code (`DownloadFailed` / cookie-rate codes / `RemuxFailed` / `PackFailed`). Cookie/rate/download/resolve failures auto soft-pause the hostname and notify via in-app log + subscribed Apprise (`cookie_invalid` / `rate_limited` / `ytdlp_failed`); remux/pack notify without pause. Never auto-change series monitored or domain active. Scan/list yt-dlp failure immediately holds remaining `wanted` as `wanted_source_error`. When a source reaches `source_download_error_threshold` wanted_download_error videos, sibling **`wanted`** → **`wanted_source_error`** (pending downloads cancelled). Source **Retry** returns those statuses to **`wanted`**. **Download now** enqueues at front of domain lane, bypasses that domain’s `max_download_queue`, and is allowed when the series is unmonitored (domain must still be active). Successful media work is buffered into a global **`download_digest`** digest (archive download or stream ready, beginning cached or not) when all media queues drain and no eligible wanted remain.

**Metadata rescan** (separate task) remains for operator backfill/refresh of indexed metadata and on-disk sidecars (NFO/thumb/**subs**) without re-downloading media. Sidecar refresh deletes prior nfo/thumb/sub files on disk before rewrite and **never** deletes or rewrites `info.json`.

## Maturity refresh (optional)

Delays live on the **quality profile** (`maturity_redownload_hours`, `maturity_sidecar_hours`; `0` = that pass off for every series on the profile). UI edits sidecar delay as **days** (stored as hours). No series flag and no domain overrides. Use a profile with both at `0` for watch-and-delete series.

Clock is `upload_date` only (missing → never). Both passes require first acquire while still young (`acquired_at` before the maturity deadline); otherwise skip forever. One-shot: media success bumps `acquired_at`; sidecar success sets `sidecars_acquired_at`.

| Pass | When | Task |
|------|------|------|
| Media | `now >= upload_date + profile redownload hours` ∧ young at acquire | `downloaded` → `download` (replace media + info.json + sidecars); `streamable` → `pack_stream` (re-pack + beginning) |
| Sidecar | `now >= upload_date + profile sidecar hours` ∧ young at acquire ∧ sidecars not yet matured | `refresh_sidecars` (NFO/thumb/subs only; orphans removed; no info.json) |

Same cron tick as download-wanted: media maturity first when both due. History: `maturity_repacked` / `maturity_sidecars_refreshed` (older rows may still use `maturity_redownload` / `maturity_sidecars`).

## Retention & file sync

1. **File sync** (`sync_files_cron`, optional): enqueues a **`sync_files`** task on the **`system`** lane (one pending/running at a time). On process start the scheduler anchors `last` to boot so missed fires while down are **not** caught up; the next cron after boot is the first opportunity. Cron does not enqueue when there are no videos. Skips roots whose path is offline; skips beginning-cache reconcile when CacheDir is offline. Runs concurrent with hostname domain work.
2. Pass: (1) `downloaded` + media gone → **`missing`** (keep file rows). (2) `missing` + media back → **`downloaded`**. (3) `streamable` + `stream_beginning_cached` but beginning gone → clear flag + history `beginning_missing` + best-effort requeue **`cache_beginning`** (setting > 0 ∧ domain active ∧ pipe-only; status stays **`streamable`**); beginning present again → set flag + `beginning_restored`. CDN HLS/progressive skipped.
3. History for kind `sync_files` only when ≥1 video changed; `tasks.detail` lists `missing_ids` / `restored_ids` / `beginning_missing_ids` / `beginning_restored_ids`.
4. **Retention delete** (`retention_delete_cron`, optional): separate **`retention_delete`** task on the **`system`** lane (one pending/running at a time). Same no-catch-up-on-boot / cron rules. Cron does not enqueue when no root has `retention_ttl_seconds`. Roots with TTL: delete expired artifacts → **`deleted`** + history `retention`; prune empty series dirs. Default root has **no** TTL. Offline roots skipped. History detail lists `retention_ids` when changed.
5. Auto download only for status **`wanted`** when **series monitored ∧ domain active** (`source_id` required). Via tip-scan `download_new_on_scan` (immediate, until domain queue full) and `download_wanted_cron` (backstop for full-scan wanted and tip-scan overflow). **Download now** is an explicit operator enqueue: front of domain lane, bypasses domain `max_download_queue`, allowed when series is unmonitored, still requires domain active. Enqueue order for download-wanted: fair round-robin across series (fewest active downloads first), within series by `download_wanted_order` (`oldest`/`newest` using `upload_date`; undated by `id`); tip-scan auto uses the same within-batch order. Per-domain `max_download_queue` (default 8) caps pending+running download + cache_beginning for auto enqueue. **Want** / **Ignore** change status only (no enqueue on Want). Unmonitored series: no tip Scan and no download-wanted; **full scan still runs**. Unmonitoring a series cancels **pending tip Scan** only (full scans keep going; running scans keep going). **Deactivate domain** cancels that host’s **pending and running** tasks. **Delete source** removes the source **and** hard-deletes all videos that belonged to it (index + library files + cancel related tasks). To keep videos and stop Scan, set interval to Never or deactivate the domain. Changing series monitored never rewrites domain active (and vice versa).

## Remux (always MKV)

Creatorr remuxes downloaded media to **MKV** via ffmpeg when needed (`library.RemuxIfNeeded` → `library.RemuxContainer`). When SponsorBlock **remove** is set, remux runs in the **`sponsorblock_cut`** task only for copy-cut (reencode already outputs MKV). Mark-only / no-remove still remux inside the download task. Quality profiles supply the format selector (`--format` / yt-dlp `-f`) and optional maturity delays. There is **no** Settings key or UI for container choice.

**Why MKV (not MP4 / webm / mov):**

- **Remux reliability with real downloads.** yt-dlp often lands **VP9 or AV1 + Opus** (webm or similar). Stream-copy remux into **MKV** usually works. Remux-only into **MP4** often fails or yields poorly compatible files (Opus-in-MP4, non-ISO codecs) unless Creatorr re-encodes - which remux deliberately does not do (`-c copy`).
- **Archive-friendly.** MKV accepts a wide codec mix and common sidecar streams without forcing an encode step at download time.
- **Streaming later is a delivery concern.** Browsers and many web UIs prefer **MP4** (or fMP4 for HLS/DASH); MKV rarely direct-plays in-browser. Media servers often remux or transcode MKV for web clients. Creatorr keeps **MKV on disk** for remux-safe storage; stream proxy (or an external media server) can present playable bytes at play time without changing the library archive format.

**Remux column:** `download_remux_container` is **NULL** when remux was skipped (already `.mkv`); **`mkv`** only when `RemuxIfNeeded` actually remuxed.

**Not configurable:** operators do not pick mp4/webm/mov. yt-dlp must not remux; Creatorr owns the post-download remux step.

**Regenerate all NFO files** (Settings → Library → Maintenance): enqueues system-lane **`regenerate_nfo`** (one pending/running; resumable cursors after restart). Rewrites episode `.nfo` beside every on-disk video from current DB metadata when bytes differ, and rewrites `tvshow.nfo` when the series folder exists; does not touch media/json/thumb and does **not** update `videos.acquired_at`. Per-episode history only when rewritten; one History outcome on the finished task on completion.

**Regenerate all .strm files** (same Maintenance section): system-lane **`regenerate_strm`** (one pending/running; resumable). Rewrites every on-disk `.strm` to the current External Creatorr URL + stream URL token when bytes differ. No yt-dlp; does not touch NFO/thumb. Run after rotating the stream token or changing the external URL.

**Clear beginning of stream cache** (same Maintenance section): system-lane **`clear_beginning_cache`** (one pending/running). Deletes `{CacheDir}/download-beginnings`, clears `stream_beginning_cached` on all videos, and cancels pending **`cache_beginning`** tasks. Does not re-cache; pack / file sync may refill when `cache_beginning_seconds` > 0.

**Clear progressive stream cache** (same Maintenance section): system-lane **`clear_playback_cache`** (one pending/running). Deletes `{CacheDir}/playback-cache`, zeros progressive cache columns. Leaves beginning caches alone.

**Apply episode format** (same Maintenance section, listed first): system-lane task `rename_episodes` renames packed `downloaded`/`streamable` episode file sets to current formats (snapshot at enqueue). Skips videos with pending/running download/pack_stream/cache_beginning/sponsorblock_cut (`skipped_busy`); double busy-check before rename. Collision / mid-set failure → fail that video, continue. Per-video history only on success (`renamed`). Format settings form locked while the task is pending/running. Series title or root changes move the series folder immediately (blocked while download/pack/cache/cut/verify tasks are busy); episode filenames that still embed the old series title need this Apply to rewrite.

## Series metadata (tvshow.nfo)

Editable show fields (plot, sorttitle, originaltitle, studio, genres, tags, actors, tagline, country, mpaa) live on the series row. Art (`poster.jpg`, `banner.jpg`, `fanart.jpg`, `clearlogo.png`) and `tvshow.nfo` live under the series folder only (not in the DB). **Fresh schema only** - wipe existing DBs to adopt new columns. Studio / genres / country / content rating / tags / actor name / actor role each use one library-wide datalist pool (`ListMetaSuggestions`) - values from **both** `series` and `videos` for that field name. Series Metadata and video Metadata share the same pools (never entity-scoped).

### Metadata suggestion pool

| Field | Pool source columns |
|---|---|
| studio | `series.studio` ∪ `videos.studio` |
| genres | `series.genres` ∪ `videos.genres` (JSON string lists) |
| tags | `series.tags` ∪ `videos.tags` |
| country | `series.country` ∪ `videos.country` |
| mpaa | `series.mpaa` ∪ `videos.mpaa` |
| actor name | names in `series.actors` ∪ `videos.actors` |
| actor role | roles in `series.actors` ∪ `videos.actors` |

Do not add a new metadata suggest field without extending this pool (both tables). Actors stay a JSON list of `{name, role}` in SQLite; genres and tags stay JSON string lists. The Metadata modal edits genres, tags, and actors as plain locked rows (Lucide chevron ↑↓ / minus / plus) plus an add row - not disabled inputs or free-text / comma fields. Form/list order is NFO order (`actors[].order` from index). Duplicate values are rejected (case-insensitive): genres/tags by string, actors by name.

**Uniqueid** stays in DB + NFO but is **not** in the Metadata editors. Prefetch/Fetch may set it; episode NFO falls back to `yt-dlp` + `remote_id` when empty. Index identity remains `remote_id` (read-only).

The series **Metadata** modal (series detail → Metadata) can prefetch from an ephemeral channel/playlist URL (not stored): playlist fills text only; channel may include poster/banner with preview thumbnails beside the file inputs before Save. Prefetch art lives under `cache/series-meta/{id}/` only until Save; Save copies into the series folder and deletes that draft (library art is the only lasting copy). Premiered is the oldest video `upload_date` (UTC day), recomputed when **any** source history becomes fully indexed. NFO `<year>` derives from premiered; `<status>` is Continuing/Ended from series monitored. First metadata save creates an empty series folder if needed. Title or root changes move the series folder (refused while download/pack_stream/cache_beginning tasks are busy; on move failure Creatorr reverts the DB field). Clearing an art slot (X on the preview) deletes the file on save.

**Add series** (Overview / Series list modal) offers two paths: **From channel / playlist URL** configures the first feed source, then enqueues interactive task `prefetch_add_series` (worker yt-dlp; wizard polls until draft ready under `cache/add-series/{token}/`) and opens series setup (editable title + library fields) - or **Create manually** with a typed title and no source (add sources later on the series page). On create, draft art is copied into the new series folder and the draft dir is removed.

## Video metadata (episode NFO)

Editable episode fields live on the video row: **title**, **plot** (`description`), sorttitle, originaltitle, studio, genres, tags, actors, tagline, country, mpaa. Season / episode / aired / remote id stay index identity (read-only in the editor). Uniqueid is not edited in the modal (same as series - see above). **sorttitle** / **originaltitle** that equal **title** are stored empty and omitted from episode NFO (redundant with `<title>`).

The video **Metadata** modal (video detail → Metadata) mirrors the series pattern: structured form → Save updates SQLite and rewrites the episode `.nfo` beside packed `video` or `.strm` (no media rename). Datalists use the same **Metadata suggestion pool** as series (see above). Fetch from URL is ephemeral (defaults to `source_url`; other hosts allowed); it fills the form only and does **not** change `remote_id` or `source_url`. Video detail header **Refresh sidecars** enqueues `refresh_sidecars` (NFO / thumb / subs beside pack anchor; never media or `info.json`). API `POST /api/videos/{id}/metadata-rescan` remains for background listing + sidecar refresh without the form.
