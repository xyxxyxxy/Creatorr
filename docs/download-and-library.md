# Download pipeline and library file lifecycle

Index: [README.md](README.md). Terminology: [`domain-model.md`](domain-model.md) (via [`AGENTS.md`](../AGENTS.md)).

## Download pipeline

1. Resolve / download via **in-tree yt-dlp** (`internal/ytdlp`) into a temp work dir. Archive downloads **always** pass `--match-filters` with `is_live!=?1` (soft-skip currently live broadcasts; missing `is_live` still passes). The format selector comes from the series **delivery mode**: **video** (default) uses the series' quality profile `format_selector`; **audio** ignores the profile selector and always requests `ba/bestaudio/b` (best available audio). yt-dlp writes **media + sidecars** (`info.json`, thumbnail, and subtitle files when Library subtitle languages are set) in one extract when possible (optional plugins under `/yt-dlp-plugins` or `var/yt-dlp-plugins`). **Archive.org feed entries** often share one `details/` URL at index while `remote_id` is `identifier/filename`; index prefers a per-entry `url` when flat-list provides it, and download/sidecar/rescan use `library.DownloadURL` to target `https://archive.org/download/{remote_id}` when the stored row still has the parent URL (no extra yt-dlp resolve). Download task progress is **per yt-dlp format**: separate video then audio each run 0→100% on the task bar (intentional reset between streams). Step total comes from yt-dlp’s post-selection info line (`Downloading N format(s): …`), not from the `-f` selector (`bv*+ba/b` may still pick one stream via `/b`). Multi-format messages label role and step (`Downloading video (1/2) 42% · 1.00MiB/s` when yt-dlp reports speed); single-format is plain `Downloading 72%` (plus ` · …/s` when present) (no `(1/1)`, no video/audio word). Merging is message-only. On success, video history **`downloaded`**.
2. When the quality profile has **SponsorBlock remove** categories: stage media+sidecars under `{CacheDir}/sponsorblock-cut/{videoID}/`, enqueue system-lane **`sponsorblock_cut`** (low priority), finish the download task (`downloaded` message notes staged for cut). Video stays **`wanted`** until cut packs. No remux in the download task on this path (reencode already writes MKV; copy-cut remuxes inside the cut task).
3. When remove is empty: **Remux** via Creatorr ffmpeg when the file extension does not already match the target container (`library.RemuxIfNeeded` for video → **MKV**, `library.RemuxAudioIfNeeded` for audio delivery → **MKA**). History event `remuxed` only when remux ran. Then **SponsorBlock** mark/chapter embed in the same download task when mark is set (or creator chapters only); audio delivery never applies **info cards** (a burned-in video overlay - no video track to draw on).
4. **`sponsorblock_cut`** (system): fetch segments; cut (copy or reencode); optional hard-cut info cards (~2s) when reencode + cards (video delivery only); remap chapters/subs; pack. Soft-fail warns on the task. History **`sponsorblock_cut`** when a cut applied. Accurate re-encode always uses bitrate-matched H.264 (AV1/VP9/VP8 sources get 1.5× video bitrate). Re-encode cut reports numeric progress for keep-segment ffmpeg and for filter-stitch when cards force a re-encode join (0–1, weighted across both passes); remux, info cards, pack, and copy-cut are message + spinner. On Linux, re-encode ffmpeg (keeps + info cards + filter stitch) runs at fixed nice 10 (not a CPU %; no Settings key); non-Linux is unchanged. Never yt-dlp `--sponsorblock-*` / `--embed-chapters`. Persist `.sponsorblock.json` beside packed media when cuts applied. Cancel deletes staging (same recovery as cancel download: re-download later).
5. **Pack** under the library root: the **video** becomes an on-disk **episode** (`library.PackMedia` / `BuildEpisodePaths`: always under `SeriesDir` (sanitized title, max 100 runes), then relative path from the series' **root folder** `episode_format`, full episode NFO via `WriteEpisodeNFO`, optional info.json + thumb + **subtitle sidecars** with language in the filename, e.g. `.en.srt` or `.en.auto.srt` for auto-only). Packed media keeps its remux container (`.mkv` video / `.mka` audio); audio delivery still packs the same TV-episode shape (episode NFO, thumb, sidecars) - it is not treated as music/albums. Thumb: prefer yt-dlp-written image beside the work media (`--write-thumbnail` with cookies/Flare); if missing, soft-fetch `videos.thumbnail_url` (same HTTP fallback as `refresh_sidecars` when no yt-dlp thumb). Default layout nests `S{year}/…` under the series folder. Before season assign / pack, archive download soft-fills empty `upload_date` from the download-time `info.json` when present (flat playlist index often lacks dates). Missing `upload_date` after that still leaves season/episode unset in the index; pack uses year-season **0**, so `{year}` expands to **`0000`** (e.g. `S0000/…`), not TV default `S1`. `CompleteDownload` may also soft-fill from packed `info.json` and rename; that rename ignores the finishing download task so it is not skipped as busy. Saving a root's format does **not** rename existing files - use **Apply episode format** (Settings → Maintenance). Successful Apply writes video history `renamed` (previous/new name). See **Episode** in [`domain-model.md`](domain-model.md). Soft-fill `videos.media_type` from packed info.json when present.
6. Write Creatorr-owned columns on video (`CompleteDownload` → `tool` / `download_format_selector` / `download_remux_container` only when remuxed / duration+resolution from info.json → history **`packed`**; sets `acquired_at` and `sidecars_acquired_at`). Creatorr does **not** run a separate sidecars / metadata rescan after download. Packed **`info.json` is download-time provenance**: write/replace only when the media file changes (archive download or maturity re-download). Creatorr **never edits `info.json` content** (copy/move only). Subtitles are **never embedded** in the media file (keeps refresh via metadata rescan / Refresh sidecars / maturity sidecar refresh).
7. **Media verify (optional):** when the quality profile has **`verify_media`**, after a successful archive pack Creatorr may enqueue system-lane **`media_verify`** (lowest priority, below `sponsorblock_cut`). Null-decode only (`ffmpeg -xerror -i … -f null -` with `-progress`). **Mature-only** when `maturity_redownload_hours` > 0: skip young first packs; verify on maturity re-download and when maturity will never run. Hours = 0 verifies every archive pack. Success → history **`verified`** (status stays `downloaded`). Fail → **keep files**, status **`verify_failed`**, history + Apprise **`verify_failed`**, task `MediaVerifyFailed`. Cancel leaves `downloaded`. New pack cancels prior verify for that video (superseded ≠ verify_failed). Import confirm checkbox **`verify`** always enqueues (ignores mature gate). Accepted: Emby may play before verify finishes or after `verify_failed`.
8. On **currently live** reject (`LiveBroadcastSkipped`, yt-dlp `is_live`): finished download task is **`done`** (not failed); video stays **`wanted`** (history `live_skipped`) so the next download-wanted pass can retry after the broadcast ends; no soft-pause; no `ytdlp_failed` notify; info notify **`live_skipped`** (in-app + subscribed Apprise) with `task_id` linking the finished task. **Queue download** still enforces live soft-skip when live is known. On **age-restricted** reject (`AgeRestricted`, yt-dlp age gate): finished download task in History (`failed`); video status **`wanted_download_error`** with history `download_failed` and `code: AgeRestricted`; no soft-pause; no `ytdlp_failed` / `cookie_invalid` notify. On **narrow live unavailable** (removed/deleted/unavailable/account terminated) when Settings **`archive_fallback`** is on and the video `source_url` is YouTube: live task finishes **`failed`** with `ArchiveFallbackQueued` (History notes Web Archive retry); video → **`wanted_archive`**; **no** `wanted_download_error` yet; **no** `ytdlp_failed` notify. Creatorr immediately enqueues a second **`download`** on domain **`archive.org`** with URL `ytarchive:{remote_id}` (no YouTube cookies; `source_url` unchanged; no Domains override row auto-created). If the archive lane is full/paused/inactive, status stays `wanted_archive` for cron backfill on the download-wanted tick. Archive pack success → `downloaded`, `acquired_via=archive`, soft-fill placeholder title/description/upload/thumb from archive `info.json`, info notify **`archive_fallback`**. Archive fail → `wanted_download_error` + normal `ytdlp_failed`. On other failure: finished download task in History (`failed`); video status **`wanted_download_error`** with history detail `stage` (`fetch` / `remux` / `pack`) and code (`DownloadFailed` / cookie-rate codes / `RemuxFailed` / `PackFailed`). Cookie/rate failures auto soft-pause the hostname and notify (`cookie_invalid` / `rate_limited`). Generic `DownloadFailed` / `ResolveFailed` and remux/pack notify `ytdlp_failed` without pause. Never auto-change series monitored or domain active. Scan/list yt-dlp failures with cookie/rate pause codes soft-pause the domain only (no per-source hold). **Download-wanted** skips enqueue for soft-paused domains and never YouTube-enqueues `wanted_archive` (archive lane owns them). Source **Retry** clears **`wanted_download_error`** and **`wanted_archive`** on that source back to **`wanted`** (cancels pending/running archive.org downloads for those videos). **Queue download** enqueues at front of domain lane, bypasses that domain’s `max_download_queue`, and is allowed when the series is unmonitored (domain must still be active). Successful downloads are buffered into a global **`download_digest`** digest when all download queues drain and no eligible wanted remain.

**Metadata rescan** (separate task) remains for operator backfill/refresh of indexed metadata and on-disk sidecars (NFO/thumb/**subs**) without re-downloading media. Sidecar refresh deletes prior nfo/thumb/sub files on disk before rewrite and **never** deletes or rewrites `info.json`. Fetch from URL stays live-only (no automatic Web Archive metadata prefetch).

## Maturity refresh (optional)

Delays live on the **quality profile** (`maturity_redownload_hours`, `maturity_sidecar_hours`; `0` = that pass off for every series on the profile). UI edits sidecar delay as **days** (stored as hours). No series flag and no domain overrides. Use a profile with both at `0` for watch-and-delete series.

Clock is `upload_date` only (missing → never). Both passes require first acquire while still young (`acquired_at` before the maturity deadline); otherwise skip forever. One-shot: media success bumps `acquired_at`; sidecar success sets `sidecars_acquired_at`. Videos with **`acquired_via=archive`** skip both media and sidecar maturity (Web Archive pack is final for media refresh). Import maturity unchanged.

| Pass | When | Task |
|------|------|------|
| Media | `now >= upload_date + profile redownload hours` ∧ young at acquire | `download` (payload `maturity: true`; replaces media + info.json + sidecars). Same delivery-mode handling as a fresh download: audio re-fetches `ba/bestaudio/b` and remuxes to MKA. |
| Sidecar | `now >= upload_date + profile sidecar hours` ∧ young at acquire ∧ sidecars not yet matured | `refresh_sidecars` (NFO/thumb/subs only; orphans removed; no info.json) |

Same cron tick as download-wanted: media maturity first when both due. History: `maturity_repacked` / `maturity_sidecars_refreshed` (older rows may still use `maturity_redownload` / `maturity_sidecars`).

## Retention & file sync

1. **File sync** (`sync_files_cron`, optional; also Settings → Maintenance → **Scan root folders**): enqueues a **`sync_files`** task on the **`system`** lane (one pending/running at a time). On process start the scheduler anchors `last` to boot so missed fires while down are **not** caught up; the next cron after boot is the first opportunity. Cron does not enqueue when there are no videos. Skips roots whose path is offline. Runs concurrent with hostname domain work.
2. Pass: (1) `downloaded`/`verify_failed` + media gone → **`missing`** (keep file rows). (2) `missing` + media back → **`downloaded`**. (3) present media whose `files.size_bytes` (non-NULL) differs from on-disk size → **`verify_failed`**, update stored size, history `file_externally_changed` (no auto re-download / no `media_verify`). NULL `size_bytes` is backfilled from disk without flagging. (4) Registered **sidecars** (`kind != video`: nfo/json/thumb/sub/…) for `downloaded`/`verify_failed`/`missing`: path gone → keep row, set `size_bytes = -1` (known missing), history `sidecar_missing` (**video status unchanged**); path back → restore size + `sidecar_restored`; present non-NULL size mismatch → update size + `sidecar_externally_changed` (no status change); NULL size backfilled quietly. No full-file hash (size only).
3. History for kind `sync_files` only when ≥1 change; `tasks.detail` lists `missing_ids` / `restored_ids` / `externally_changed_ids` / `sidecar_missing` / `sidecar_restored` / `sidecar_changed`.
4. When media or sidecar `missing` / size-changed non-empty, one alert digest **`file_sync_issues`** (in-app + subscribed Apprise) lists both sections (sidecar lines include `kind: basename`). Restores are not included.
5. **Retention delete** (`retention_delete_cron`, optional): separate **`retention_delete`** task on the **`system`** lane (one pending/running at a time). Same no-catch-up-on-boot / cron rules. Cron does not enqueue when no root has `retention_ttl_seconds`. Roots with TTL: delete expired artifacts → **`deleted`** + history `retention`; prune empty series dirs. Default root has **no** TTL. Offline roots skipped. History detail lists `retention_ids` when changed.
6. Auto download only for status **`wanted`** when **series monitored ∧ domain active** (`source_id` required). Via `download_wanted_cron` (and **Queue download**). **Queue download** is an explicit operator enqueue: front of domain lane, bypasses domain `max_download_queue`, allowed when series is unmonitored, still requires domain active. Enqueue order for download-wanted: fair round-robin across series (fewest active downloads first, then oldest/never last download enqueue, then `series_id`), within series oldest `upload_date` first (undated by lowest `id`). Per-domain `max_download_queue` (default 8) caps pending+running download tasks for auto enqueue on that hostname only; other domains keep filling until their caps (pass stops early once every active candidate domain is full). **Want** / **Ignore** change status only (no enqueue on Want). Unmonitored series: no **scheduled** tip Scan and no download-wanted; **manual tip Scan**, **full scan**, and **Queue download** still run (domain active required). Unmonitoring a series cancels **pending tip Scan** only (full scans keep going; running scans keep going). **Deactivate domain** cancels that host’s **pending and running** tasks. **Delete source** removes the source **and** hard-deletes all videos that belonged to it (index + library files + cancel related tasks). To keep videos and stop Scan, set interval to Never or deactivate the domain. Changing series monitored never rewrites domain active (and vice versa).

## Remux (video MKV / audio MKA)

Creatorr remuxes downloaded media via ffmpeg when needed, container chosen by series **delivery mode**:

- **Video** (default): remux to **MKV** (`library.RemuxIfNeeded` → `library.RemuxContainer`). Maps video + audio only (`-map 0:V -map 0:a? -dn`) so QuickTime timecode / other data streams from progressive MP4 sources do not break Matroska stream-copy.
- **Audio**: remux to **MKA** (`library.RemuxAudioIfNeeded` → `library.RemuxAudioContainer`). Maps audio only (`-map 0:a -dn`) since the source is already an audio-only yt-dlp download (`ba/bestaudio/b`).

When SponsorBlock **remove** is set, remux runs in the **`sponsorblock_cut`** task only for copy-cut (reencode already outputs the target container). Mark-only / no-remove still remux inside the download task. Quality profiles supply the format selector (`--format` / yt-dlp `-f`, video delivery only) and optional maturity delays. There is **no** Settings key or UI for container choice.

**Why MKV for video (not MP4 / webm / mov):**

- **Remux reliability with real downloads.** yt-dlp often lands **VP9 or AV1 + Opus** (webm or similar). Stream-copy remux into **MKV** usually works. Remux-only into **MP4** often fails or yields poorly compatible files (Opus-in-MP4, non-ISO codecs) unless Creatorr re-encodes - which remux deliberately does not do (`-c copy`).
- **Archive-friendly.** MKV accepts a wide codec mix and common sidecar streams without forcing an encode step at download time.
- **Playback is a delivery concern.** Browsers and many web UIs prefer **MP4**; MKV rarely direct-plays in-browser. Media servers often remux or transcode MKV for web clients. Creatorr keeps **MKV on disk** for remux-safe storage and leaves playback to an external media server.

**Why MKA for audio:** same stream-copy reasoning as MKV, scoped to an audio-only container so podcast-like VOD audio packs without a dummy video track.

**Remux column:** `download_remux_container` is **NULL** when remux was skipped (already the target extension); otherwise **`mkv`** (video) or **`mka`** (audio) when a remux actually ran.

**Not configurable:** operators do not pick the container directly (only **delivery mode**, which implies it). yt-dlp must not remux; Creatorr owns the post-download remux step.

**Regenerate all NFO files** (Settings → Maintenance): enqueues system-lane **`regenerate_nfo`** (one pending/running; resumable cursors after restart). Rewrites episode `.nfo` beside every on-disk video from current DB metadata when bytes differ, and rewrites `tvshow.nfo` when the series folder exists; does not touch media/json/thumb and does **not** update `videos.acquired_at`. Per-episode history only when rewritten; one History outcome on the finished task on completion.

**Apply episode format** (Settings → Maintenance): system-lane task `rename_episodes` renames packed `downloaded` episode file sets to each video's root `episode_format` (per-root snapshot at enqueue). Skips videos with pending/running download/sponsorblock_cut/media_verify (`skipped_busy`); double busy-check before rename. Collision / mid-set failure → fail that video, continue. Per-video history only on success (`renamed`). Root episode format fields locked while the task is pending/running. Series title or root changes move the series folder immediately (blocked while download/cut/verify tasks are busy); episode filenames that still embed the old series title need this Apply to rewrite.

## Series metadata (tvshow.nfo)

Editable show fields (plot, sorttitle, originaltitle, studio, genres, tags, actors, tagline, country, mpaa) live on the series row. Art (`poster.jpg`, `banner.jpg`, `fanart.jpg`, `clearlogo.png`) and `tvshow.nfo` live under the series folder only (not in the DB). Studio / genres / country / content rating / tags / actor name / actor role each use one library-wide datalist pool (`ListMetaSuggestions`) - values from **both** `series` and `videos` for that field name. Series Metadata and video Metadata share the same pools (never entity-scoped). **sorttitle** / **originaltitle** that equal **title** are stored empty and omitted from tvshow NFO (redundant with `<title>`). Prefetch fills draft `title` for Add series naming; it does not copy that name into sorttitle / originaltitle.

### Metadata suggestion pool

| Field | Pool source columns |
|---|---|
| studio | `series.studio` ∪ `videos.studio` |
| genres | `series.genres` ∪ `videos.genres` (JSON string lists) |
| tags | `series.tags` ∪ `videos.tags` |
| country | `series.country` ∪ `videos.country` |
| mpaa | `series.mpaa` ∪ `videos.mpaa` ∪ US TV Parental Guidelines defaults (`TV-Y` … `TV-MA`; free-text still allowed) |
| actor name | names in `series.actors` ∪ `videos.actors` |
| actor role | roles in `series.actors` ∪ `videos.actors` |

Do not add a new metadata suggest field without extending this pool (both tables). Actors stay a JSON list of `{name, role}` in SQLite; genres and tags stay JSON string lists. The Metadata modal edits genres, tags, and actors as plain locked rows (Lucide chevron ↑↓ / minus / plus) plus an add row - not disabled inputs or free-text / comma fields. Form/list order is NFO order (`actors[].order` from index). Duplicate values are rejected (case-insensitive): genres/tags by string, actors by name.

**Uniqueid** stays in DB + NFO but is **not** in the Metadata editors. Prefetch/Fetch may set it; episode NFO falls back to `yt-dlp` + `remote_id` when empty. Index identity remains `remote_id` (read-only).

The series **Metadata** modal (series detail → Metadata) can prefetch from an ephemeral channel/playlist URL (not stored): playlist fills text only; channel may include poster/banner with preview thumbnails beside the file inputs before Save. Prefetch does **not** auto-fill **studio** from channel/uploader; it does **not** auto-fill actors (channel names are not people). Prefetch art lives under `cache/series-meta/{id}/` only until Save; Save copies into the series folder and deletes that draft (library art is the only lasting copy). Cancel reloads the form from saved series fields and discards the draft (and cancels a still-running prefetch). Premiered is the oldest video `upload_date` (UTC day), recomputed when **any** source history becomes fully indexed. NFO `<year>` derives from premiered; `<status>` is Continuing/Ended from series monitored. First metadata save creates an empty series folder if needed. Title or root changes move the series folder (refused while download/sponsorblock_cut/media_verify tasks are busy; on move failure Creatorr reverts the DB field). Clearing an art slot (X on the preview) deletes the file on save.

**Add series** (Overview / Series list modal) offers two paths: **From channel / playlist URL** configures the first feed source, then enqueues interactive task `prefetch_add_series` (worker yt-dlp; wizard polls until draft ready under `cache/add-series/{token}/`) and opens series setup (editable title + library fields) - or **Create manually** with a typed title and no source (add sources later on the series page). Submit is AJAX (`Accept: application/json`); create errors (e.g. title already used under the same root) stay in the modal with the draft intact so the operator can fix the title. On create, draft art is copied into the new series folder and the draft dir is removed.

**Add video** (Import Match modal for now; reusable partial for later series use): Fetch URL enqueues interactive `prefetch_add_video` (draft under `cache/add-video/{token}/`), then `POST /api/series/{id}/videos` with `draft_token`. Manual path: title + upload date; optional remote_id (else generated). Created videos are status **`ignored`** (Want later to download). Remote ID is never user-editable.

## Video metadata (episode NFO)

Editable episode fields live on the video row: **title**, **upload date** (`upload_date` / NFO aired), **plot** (`description`), sorttitle, originaltitle, studio, genres, tags, actors, tagline, country, mpaa. Season / episode / remote id / source URL stay index identity (read-only in the editor). Uniqueid is not edited in the modal (same as series - see above). **sorttitle** / **originaltitle** that equal **title** are stored empty and omitted from episode NFO (redundant with `<title>`).

**Upload date Save:** UTC date input plus optional time input (joined). Date-only → midnight UTC (same-day date-only Save keeps the existing timestamp). Time set → stored as that UTC clock. Empty date clears `upload_date` and season/episode. Changing the calendar day (or same-day clock time) reindexes that series day and **renames packed file sets** when the path changes (same busy-skip as Apply episode format). Title-only Save still does not rename.

**Soft-fill (auto enrichment):** scan and metadata rescan only fill **title**, **description**, and **thumbnail_url** when the column is empty (first-seen / operator values are never clobbered). Metadata rescan also soft-fills empty **upload_date** (then day reindex). Settings → Library → **Metadata** (default on): **`metadata_domain_tag`** prepends the source domain to video **tags** on archive pack and Metadata Save when `source_url` is known; **`metadata_genres_from_categories`** merges yt-dlp **categories** into **genres** when categories are known. When a setting is off, Creatorr does not set that field on pack/Save/Fetch. When on, managed values are locked in the video Metadata editor (`Managed by Creatorr` tooltip) and re-merged on pack/Save; when off, previously auto values are normal editable rows. Not retroactive until next pack or Save. Metadata Save, import NFO, and Fetch→Save still overwrite other editable fields (operator intent). Episode NFO is always written from the current DB row (including archive/maturity pack).

**Import sidecars:** inbox (or in-place library) media import packs companion files beside the video: `info.json`, `{stem}-thumb.{ext}` / `{stem}.thumb.{ext}` / same-stem images (including when the media filename has a `[remote id]` bracket the thumb omits), and subtitle files. Packed thumbs are registered as `files.kind=thumb`. After a successful import, if `source_url` is known, Creatorr soft-enqueues `rescan_metadata` with `gap_fill: true`: soft-fill empty episode fields (plot/`description`, title, `thumbnail_url`, `upload_date`, genres from categories), rewrite the library episode NFO from the DB, and add missing thumb/subs from the source. Present thumbs and subtitle files stay. Never rewrites packed `info.json`. Import still succeeds if enqueue or later fetch fails.

**Import / attach `.nfo`:** data import only when a same-basename video sits beside the NFO (bundled with untracked media import, or orphan beside packed library media). Applies editable columns into SQLite (plus soft-fill `upload_date` from `<aired>` only when empty, and soft-fill `duration_seconds` from `<durationinseconds>` or `<runtime>` minutes when empty). Orphan `.nfo` with no sibling video is listed only (not Match/Attach). Season / episode / `remote_id` stay index identity. Creatorr then regenerates the library episode `.nfo` from the DB (Creatorr format). Foreign XML is never registered as provenance and is not moved into the library; a leftover source path that is not the media-stem `.nfo` is removed after apply. History event `nfo_applied` (older rows may still use `nfo_imported`). Later **Regenerate all NFO** / Metadata Save therefore rewrite from DB, not from a copied foreign file.

**Import duration:** after import complete, when `duration_seconds` is still empty, Creatorr soft-fills from packed `info.json` (same as archive), then NFO (above), then ffprobe on the media file. Probe failure leaves duration empty (import still succeeds).

**Delete sidecar (UI):** registered `files` rows of kind `sub`, `thumb`, or `other` can be deleted from the video Files table or file detail page (confirm modal). Sync: unlink that path, drop the row, history `sidecar_deleted` (system bookkeeping task `delete_sidecar`). Does not change video status. Not offered for media, NFO, `info.json`, or SponsorBlock plans.

The video **Metadata** modal (video detail → Metadata) mirrors the series pattern: structured form → Save updates SQLite and rewrites the episode `.nfo` beside packed media. Upload date changes may rename packed files; title alone does not. **Images:** one Thumbnail slot (same art-slot UX as series) when a pack anchor exists; Save installs `{stem}-thumb{ext}` + `files.kind=thumb`, or clears on X. Prefetch may soft-download the resolve thumbnail into `cache/video-meta/{id}/art-{tid}/` for preview until Save (then library thumb is the lasting copy). Without a pack, the slot is hidden with a short note. Datalists use the same **Metadata suggestion pool** as series (see above). Fetch from URL is ephemeral (defaults to `source_url`; other hosts allowed); it fills the form (and optional thumb preview) and does **not** change `remote_id` or `source_url`. Video detail header **Refresh sidecars** enqueues `refresh_sidecars` (NFO / thumb / subs beside pack anchor; never media or `info.json`) to re-fetch from the source. API `POST /api/videos/{id}/metadata-rescan` remains for background listing + sidecar refresh without the form.
