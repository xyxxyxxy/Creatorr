# UI (HTMX + daisyUI)

Index: [README.md](README.md). Agent contract: [`AGENTS.md`](../AGENTS.md).

**CSS.** Tailwind 4 + daisyUI 5. Source: [`internal/web/ui/src/input.css`](../internal/web/ui/src/input.css) (`@import "tailwindcss"` + `@plugin "daisyui"`) → committed [`internal/web/static/app.css`](../internal/web/static/app.css). `make css` also vendors **ECharts** and **Lucide**. After class or vendor bumps, run **`make css`**. Themes: curated daisyUI set on Settings → General **Appearance** (Dark / Light / Special); default follows OS (`emerald` / `dark`); override stored in `localStorage` key `creatorr-theme` (this browser only).

**Dev UI reload:** `CREATORR_WEB_DEV=1` (+ optional `CREATORR_WEB_DIR`, default `internal/web`) reloads templates/partials/static from disk each request. Compose mounts `./internal/web` at `/web`. CSS still needs `make css`.

**CSS priority (daisyUI first).** Fix UI with **stock daisyUI + Tailwind** in templates/partials, or daisy **theme tokens** via `@plugin "daisyui/theme"`. Prefer changing the HTML pattern over CSS.

When stock daisyUI is almost right but needs a small glue fix (overflow, stacking, clip): **prefer a minimal rule in `input.css`** over JS portals, third-party tooltip/popover libs, or other UI kits. Document each override with a one-line why. Do **not** add another CSS/UI library for chrome daisyUI already covers. If the fix is large or unclear → **stop and ask**.

**Current override:** `.modal` / `.modal-box` overflow in `input.css` so daisyUI tooltip tails are not clipped inside modals (scroll the overlay instead of the box). Import list/summary: raise `#import-list` / `#import-summary-tree` tooltip hosts on hover so daisyUI tip bubbles are not covered by sibling filename/Match chrome. Metadata ordered lists (genres/tags/actors): CSS counters on `[data-list-ord]` so row numbers track up/down without JS. List filter date/`datetime-local` join-item: transparent native control + min width so crush in the Filter join does not nest UA chrome. Form `validator`: neutralize daisyUI `:user-valid` success green so only invalid fields get error color (`aria-invalid` / `:user-invalid`); neutralize skips hosts with `aria-invalid` so client errors still paint red on empty optional fields. `.tooltip-nowrap`: keep long `data-tip` on one line in monospace (quality profile format selectors; stock daisyUI wraps at 20rem). Video detail thumb cell (`.video-detail-thumb`): hidden below Tailwind `md` (48rem); `4.5rem` / `6.5rem` at `md` / `lg` (same stages as shell: `md:p-6`, `lg` navbar breakpoint).

**Icons.** [Lucide](https://lucide.dev) (ISC). Use `<i data-lucide="name" class="size-4"></i>`. `app.js` calls `lucide.createIcons()` on load and after HTMX swaps.

**Nav:** Series | Tasks | Import | History | Stats | Settings - brand **Creatorr** → Overview (`/`). Overview shows library stats; when any task is `running`, a **Running tasks** list (all domains combined; kind → task detail, queue domain/`system` beside kind, series/video links, message, progress; no Cancel) above **Recent additions** (newest `downloaded` across all series by `acquired_at`, same row chrome as series Videos, no delivery/want/ignore actions; series title in the meta line). Shell: sticky daisyUI navbar inside a shared `app-shell` column (`max-w-5xl` ~1024px, `min-width: 48rem` = Tailwind `md` in `input.css`) so the column never sits below `md` (avoids `p-4`/`md:p-6` width jump) and narrower viewports scroll horizontally (`partials/nav.html`, `partials/head.html`) - `navbar-start` brand + mobile hamburger dropdown (`lg:hidden`, `menu-lg` + larger Lucide icons); `navbar-center` horizontal menu (`lg+`); `navbar-end` bell dropdown **Notifications** (daisyUI `menu` of latest 4 in-app notifications with unread rows `menu-active`, **Mark all as read**, and **View all**; unread alert/warning badge) + user icon dropdown (logged-in username + **Log out**). Settings is a `details` submenu (General, Library, Connect, Queue / Domains, Scheduler, Maintenance); it does not stay `open` after navigating to a settings page (Settings summary stays `active`). Series nav: inline error badge after the label (`badge-sm`) = count of series with video error statuses or a source scan_error (`GET /series/error-count.json`; hides when 0; refreshed with Tasks badges on SSE + 15s poll). Tasks nav: inline primary badge = active task count excluding soft-paused domains; warning badge = soft-paused domain count (both can show). Task detail: `/task/{id}` (pending/running/finished; HTMX log Refresh / load swap scrolls the log pane to the bottom). History (`/history`): page-header **From** / **To** (`from`/`to` UTC `datetime-local`, shared by both sections; empty = all time) then **Notifications** (opening History marks all unread alerts/warnings read; filters `nlevel` type, page `npage`) then **Tasks** (filters `domain`/`kind`/`status`, page `page`). Notification list columns: icon (bell = info / amber `siren` = warning / red megaphone = alert, daisyUI tooltips), Event, When, Title. Rows → `/notification/{id}` (title + level icon; **Message** body text; **Related to** with task kind/status/domain/message plus video links when available including `download_digest`; no read timestamp or channels row; opening marks unread alert/warning read). Task rows → `/task/{id}`. Task history columns: Domain, Kind, When, Message (`error_code` / detail JSON on task detail only). Task **Detail** panel shows outcome JSON (e.g. scan `created_ids`) plus per-event video lists from `video_history` for that task (linked titles, same shape as discover). Task **Commands** panel (when any) shows shell-quoted yt-dlp/ffmpeg/ffprobe lines from `tasks.commands`, with a Pretty toggle like JSON sidecar view.

**Reuse / wrap first** - compose from `internal/web/templates/` and `internal/web/partials/`. When chrome would repeat, create or extend a shared partial. Any [daisyUI](https://daisyui.com/components/) component is fair game when it fits.

## Patterns

- **Import page:** Scan/import UI always available (series can be created from Match → **Create new series**). Shared add-series modal on `'Import'` checks and disables `'Mark new videos as ignored'` with a tooltip. Page help recommends creating the series and sources with `'Mark new videos as ignored'` first so a video index is available to match the files automatically (File matching daisyUI `collapse` under the page header with help list and series-first info alert; incomplete `'Full scan'` note above the file list is warning). On load, the page shell paints immediately; then in parallel it fetches the Match catalog (`GET /api/import/picker`) and runs one Scan for the selected folder (default inbox) unless any pending/running `import` task already exists. Leaving the page aborts in-flight picker/scan fetches (no error toast for navigate-away cancel). While any `import` task is pending or running, the candidate list is replaced by a loading spinner plus a link to **Tasks** (`/tasks`); Scan folder, **Rescan**, and bulk Import actions stay disabled until the queue drains (live via SSE + `GET /actions/import-busy-status`; after **Import now** queues at least one item the busy shell shows immediately; when the last import finishes the page auto-rescans). `POST /api/import/scan` returns conflict while imports are queued or running. The file list shows a loading spinner until Scan candidates return; Match stays gated until the picker catalog is ready (long scans skip the usual 60s API request timeout). While any source still has an incomplete `'Full scan'` (`full_scan_done=0`), a warning alert above the file list notes that not all videos may be indexed yet for auto-match (wording is about incomplete index, not a running scan task; live-hides via SSE when scans finish). After Scan, candidates render as a vertical `<ul>` of bordered list items (not a table) - one item per stem group (media + sidecars; group key casefolds and strips `[id]` so NFO/thumb without matching brackets still merge), sidecar-only Attach groups, or non-importable other files. Each importable row: file stack + match note on the left (auto-match label until Match changes the target; then `Matched to Series / Title`, `Attach to …`, or `Create new video: Title on Series`); right side icon actions vertically centered - status `check` (matched) / `circle-dashed` (not matched) / `x` (not importable) at `size-6`, then `gap-3`, then Match action (`link` Match when unmatched / `unlink` Unmatch when matched; `btn-primary` unmatched / `btn-soft btn-primary` matched; disabled soft `link` on non-importable rows). Unmatch clears the pick so Match can be opened again. No inline series/video summary text. File rows show primary full path with role icon; same-stem sidecars as `+ N sidecars` then role icons (no tooltips on role icons). Auto-match note omits the remote ID value (`Matched by remote ID to Series / Title`). Empty scan shows a daisyUI `alert` (same as Tasks empty); match count hidden while no files. With files: status line has file/item counts on the left and unique matched videos/series on the right. Toolbar: one row with **Auto-match** (re-applies scan suggestions to every importable item; disabled after Scan/library switch or Auto-match until a Match/Unmatch/bulk series pick or **Reset matches**), **Reset matches** (clears series/video picks on every importable item), **Pick series for all unmatched** (opens Match series-only; picking a series applies it to every importable item that still has no series) as a daisyUI `join`, then **Show only unmatched**, and **Import** right (count of ready items; [aura-rainbow](https://daisyui.com/components/aura/#aura-rainbow) when every importable item is matched, ignoring listed-only). Scan folder select auto-scans on change (and once on page load); joined **Rescan** re-scans the same folder for new files without clearing current matches. Folder change, **Rescan**, and **Auto-match** show a flash toast with how many scan auto matches were found (`N auto matches found.` / `No auto matches found.`; initial page-load scan stays quiet). Match modal: fixed `h-[90vh]` (lists fill leftover height); series-only Pick series uses `max-w-2xl` (half of two-pane `max-w-4xl`); name search, series list (poster) and video list (thumb) - less detail than the main library lists; selecting a series locks that list to one row with X to change; selecting a video (or finishing Add video index) applies immediately and closes Match; series list always offers **Create new series** (opens shared Add series modal with the same **From channel / playlist URL** / **Create manually** choice as Overview; on `'Import'`, `'Mark new videos as ignored'` is checked and disabled with a tooltip; on success stays on `'Import'`, locks that series in Match); **Create new video** is always at the top of the media Match video list (pick a series first if none locked) and opens the shared **Add video** modal (`partials/add_video_modal.html`; reusable markup, Import-only wiring for now - not on series Videos yet). Add video: Fetch URL is primary (interactive `prefetch_add_video` → draft under `cache/add-video/{token}/`; then `POST /api/series/{id}/videos` with `draft_token`); manual fallback is Title + Upload date only with read-only Remote ID from file hints or generated on create; new row status is **`ignored`**. On success Match applies the real `video_id` and closes. Series-only scan suggestions fill the series and leave the video empty (operator picks or creates a video in `'Match'`; scan never auto-CREATE). Search disabled while a prior video pick is locked for change; **Allow matching existing media** only shown for media match (hidden for sidecar attach); when off, media Match omits packed media; sidecar Attach hides Create new series / Create new video and only lists videos that already have packed library media; **Allow matching existing media** lives in that modal (off by default: omits packed media; when on, includes them with `· has media` and import deletes that media then installs the new file). A given indexed video can be matched to at most one media import item (always hidden from other Match lists once claimed; duplicates from scan auto-suggest are scrubbed). **Import** opens a read-only summary tree (series → episode → full paths with role icons; NFO rows note used for metadata and re-generated on import); summary warns when any item will replace existing media; **Import now** (secondary) queues without verify; **Import now and verify media** (primary, rightmost) queues with `verify=true`. **File matching** collapse with rules list (above the series-first info alert) covers ID / title / series / sidecar basename. Scan folder sits below. Orphan `info.json` is listed only (provenance; packs with media bind/import, never attach alone). `.nfo` / orphan thumb are metadata-or-art only with a same-basename sibling video (media import group or beside packed library media); alone they are listed only. Orphan/sibling apply updates editable metadata then regenerates the library episode NFO from DB (source XML not kept).

- **Tasks page:** page intro has two help paragraphs (queues by domain; pause vs interactive metadata prefetch). Lane header: line 1 `{domain}` (`text-warning` when paused); line 2 limit chips on the left (only when the lane has open or scheduled rows; Lucide `list`/`timer`/`layers-2`/`download`/`snail`/`cookie`/`flame`/`key-round` matching Domain override form order: queue → parallel → cooldown → rate → sleep → cookies → Flare → credentials; rate chip shows binary units e.g. `10MiB/s`; Domain-default muted, host override full strength) and host queue status on line 1 left of History (always: label + `h-2` progress; paused = `Paused` + warning bar (full when quiet; label `Paused, no tasks` when the lane has no open rows; indeterminate busy slide while tasks still running, tooltip `Some active tasks remain`); cooling = `Cooldown` + primary fill counting down (tooltip: remaining wait before next task; client does not paint Idle when the timer hits 0 if pending/running rows imply Busy/Active); idle = muted `Idle` + empty bar (label `Idle, no tasks` when the lane has no open rows); active = `Active` + indeterminate primary bar when running with free slots (tooltip: free parallel slots); busy = `Busy` + indeterminate primary bar when running >= max parallel (tooltip: max parallel reached); Cancel all pending sits immediately right of that progress, still left of History). `system` title only (no limit/cooldown row). Each lane shows one daisyUI `list` of open tasks (running first), paged at 20 (`TaskPageSize`; per-lane query `p_example_com` so paging one host does not page others; `system` scheduled rows stay above the paged list); empty lane omits the list (no `list_empty` alert; quiet Idle/Paused labels carry `no tasks`). Every task row puts a progress bar on the right (vertically centered with Cancel): pending = empty secondary bar (`value=0`); running with mid progress = determinate secondary; running at 0%/100%/nil = [indeterminate](https://daisyui.com/components/progress/#indeterminate-without-value) busy. Host lanes: title-line queue status + Cancel all, then History, then Pause/Resume.  Nav Tasks shows a warning badge with the count of soft-paused domains (`#tasks-paused-badge`, from `GET /api/domains/paused`).

Download rate UI uses binary labels (`KiB/s` / `MiB/s` / `GiB/s`; stored as yt-dlp `K`/`M`/`G`). Access on defaults is an info alert only (FlareSolverr / cookies / credentials are **override-only**). Domain overrides list (operator Add/Edit/Delete - limits + Access; **no** Active column). Override Access: Netscape cookies jar with export guide, FlareSolverr checkbox (**On** needs `CREATORR_FLARESOLVERR_URL`; disabled with `(disabled)` until then), and a **Credentials** fieldset (membership help + 2-col [label-for-input](https://daisyui.com/components/label/#label-for-input) `'Username'` | `'Password'`; password column uses daisyUI `validator` + sibling `validator-hint` under the input; when a password is already stored: join `'Password'` label | `'Reset stored'` button; click swaps to the password input). Overrides table shows Lucide `key-round` when the host row sets a non-empty username (empty when NULL inherit). Shared override modal (Domain, then Domain Queues / yt-dlp throttling / Access grouped fieldsets matching Domain defaults; diff vs default + per-field reset icon joined to limit controls only; FlareSolverr is a checkbox - disabled until `CREATORR_FLARESOLVERR_URL` is set); Download rate limit is a daisyUI join (number + `K/s`/`M/s`/`G/s`/Unlimited), not free-text. Hostname editable on Add and Edit (datalist of source hosts); Save upserts the posted hostname only (changing it leaves the previous override row). Missing host row = active + defaults. Inactive host (API) → actions disabled (tooltip → `'Settings → Queue / Domains'`). On `/tasks`: **`system` always shown first** (one-at-a-time maintenance / SponsorBlock cuts; no cooldown), then every known host (domains rows + source URL hostnames + soft-paused hosts), even with zero tasks - no page-level empty state. Lane headers: paused badge, Pause/Resume, effective download rate (when not Unlimited) / sleep, cookie icon, **credentials** `key-round` chip (full strength on host override; muted when default-only or absent), FlareSolverr shield when Use Flare is effective (muted = enabled; `text-info` = warm browser session), cooldown countdown on host lanes.
