# UI (HTMX + daisyUI)

Index: [README.md](README.md). Agent contract: [`AGENTS.md`](../AGENTS.md).

**CSS.** Tailwind 4 + daisyUI 5. Source: [`internal/web/ui/src/input.css`](../internal/web/ui/src/input.css) → committed [`internal/web/static/app.css`](../internal/web/static/app.css). `make css` also bundles JS with esbuild (ES modules in [`internal/web/ui/src/js/`](../internal/web/ui/src/js/) -> committed `internal/web/static/app.js`; the import page script `src/js/import.js` -> `static/import.js`) and vendors ECharts and Lucide. Edit the sources, never the bundles. Keep a Go-guarded comment as `//!` (esbuild drops other comments). After class or vendor bumps, run `make css`. Themes: curated daisyUI set on Settings → General **Appearance** (Dark / Light / Special); default follows OS (`emerald` / `dark`); override is this browser only (`localStorage` key `creatorr-theme`).

**Dev UI reload:** `CREATORR_WEB_DEV=1` (optional `CREATORR_WEB_DIR`, default `internal/web`) reloads templates and static files each request. Compose mounts `./internal/web` at `/web`. CSS still needs `make css`.

**Document title:** the browser tab is always `Creatorr`. In-page headers still use the page title.

**daisyUI first.** Stock daisyUI + Tailwind in markup, or daisy theme tokens. Prefer a different HTML pattern over custom CSS. A small glue fix (overflow, stacking, clip) belongs in `input.css` with a one-line why. Do not add another UI kit. A large or unclear fix: stop and ask.

Glue already in `input.css` (the why, not the selectors):

- Modal tips must paint outside the box, so the overlay scrolls and the box does not clip. Modals sit above the shell navbar. Tall previews without tips scroll inside the box.
- The bell menu and flash toasts sit above open modals. Toasts sit below the navbar so they do not cover the bell.
- Import list and summary tips rise above the next row on hover.
- Genre, tag, and actor rows number themselves so reorder does not need JS.
- Filter date fields stay transparent and wide enough that the browser control does not look nested.
- List-view `q_field`: uses `.select.join-item` (search icon + field select; stock daisyUI caret).
- List-view toolbar is one join: optional Multi-select + `q_field` (search icon inside the field control) + search input + Filter / Sort / View. Filter/Sort/View wrappers use `.input.join-item` (same field chrome as search; borderless triggers; no nested `btn join-item`). Menus use `dropdown-bottom dropdown-end` (open below, end-aligned) with roomy widths (Filter `w-80`, Sort `w-64`, View `w-52`). Sort shows direction on the selected option (up/down arrow); re-selecting that option toggles `dir=asc|desc` (field default when omitted). An open Filter/Sort/View menu stacks above later list toolbars on the same page (series-detail Sources over Videos); hovered tips stay above menus. Hidden explorer `type`/`at` (and scope) fields sit before the first `.join-item`; `input.css` rounds the first `.join-item` so Multi-select keeps the join start radius.
- Validators show error only. A valid field stays neutral, including after Save on an empty optional field.
- Long format-selector tips stay one monospace line.
- A bulk-selected list row is square so the selection fill covers it.
- A radio join highlights the checked choice.
- The app column is at least the `md` width so page padding does not jump; narrower viewports scroll sideways.
- Configurable list tables (`[data-list-table]`): wide tables scroll sideways in the wrap so sticky Title/Actions stay in the panel; Title (and select when shown) stick left, Actions stick right on video tables. Table chrome is one row above the wrap: Columns then dataset summary left, pager right when multi-page (so the columns menu is not clipped). Pager also sits below the wrap. Non-table paginated Explorers show the same pager above and below the rows. Column headers that match a Sort toolbar field are whole-cell HTMX links (same apply/toggle-dir URLs as Sort); active sort shows `aria-sort` and a muted up/down arrow. Toolbar Sort stays for fields with no visible column (e.g. series Date added / Last upload); no extra chip when the active sort has no column.
- Hovered daisyUI tips raise above page chrome (filter join, sticky cells, later rows); stay below the shell navbar and modals.

**List load modes** (orthogonal to View `list` | `cards` | `gallery` | `table`):

| Mode | Behavior | Size (v1) | Where |
|------|----------|-----------|--------|
| **paginated** | One page + pager (`?page=`; table: summary/columns above, pager below) | 10 | Table view on `/series`, `/videos`, Browser (all types), and Sources Explorer; series detail Videos (all views); series/video detail Files embeds (list and table) |
| **infinite** | Chunk + HTMX sentinel append; keep-depth `?through=` | 20 | Browser list views for every type (Series / Sources / Videos / Files / Tasks / Notifications); `/series` and `/videos` list\|cards\|gallery |
| **fixed** | One shot of N; no pager, no sentinel, no `through` | 4 / 10 | Overview Recent tasks (list, 4) + Recent additions (gallery, 10) |

**Browser list never paginated.** On `/browser`, list view is always **infinite** for every Explorer type. Table stays paginated. Do not add a paginated Browser list; use `libraryListMode(viewMode)`.

Infinite browse auto-loads up to 500 rows; a full live refresh (Want/Ignore/Delete, etc.) caps at 100 rows and scrolls the list to the top when clamped. Paginated and fixed ignore `through` if present. Bulk selection Sets survive append and capped refresh (ids past the rendered prefix stay selected in memory without checkboxes until those rows load again). Filter/Sort/View resets `through`. The infinite sentinel paints daisyUI skeleton placeholders for the **next chunk only** (count = min(chunk, remaining)) as a loading affordance. It does not reserve height for the rest of the result set, so the scrollbar cannot scrub far past loaded rows and leave pagination catching up. The scrollbar thumb will grow as each chunk appends.

## Patterns

- **Bulk confirm.** Every multi-select bar action follows one confirm policy (shared `*_BULK_CONFIRM_AFTER = 5` in each `*_bulk.js`):
  - **One-shot actions** (Monitor / Unmonitor, Want / Ignore, Refresh sidecars, Clear errors, Check integrity, Scan, Mark read / Mark unread, and any new submit-without-form bulk): confirm only when more than 5 are selected; ≤5 submit immediately. Confirm copy names the count (e.g. `Scan N sources`, `Mark read N notifications`, `Want N/M videos`).
  - **Delete** always opens a confirm modal (any selection size), including impact copy when that action has it.
  - **Edit / Edit metadata** always open their form modal (editor, not a yes/no confirm).
  New bulk actions must pick one of these three buckets. Do not invent a fourth confirm style; Ask when ambiguous.
- **Chrome.** One treatment per role. Primary is the main commit (Save, Add, verify-import). Secondary is a second add beside a primary add. Outline is a labeled page-navbar action. A plain button is an icon-only action that is not destructive, and modal Cancel / Keep. Soft error is a delete trigger; the confirm submit is solid error. A settings-list delete that is not joined to Edit is a ghost button with error text. Muted is for empty or inherited values and for disabled label text. Mute the text, not a tooltip or anything that wraps one (opacity fades the tip). daisyUI already fades a disabled checkbox; do not fade it again. Warning means paused or recoverable, error means failed or blocked, success means healthy or complete. An active list filter uses the primary field color. A disabled control does not receive hover, so put the tip on a wrapper (inside a join, `aria-disabled` on the button instead, so the seam stays one control). Tailwind class names must appear whole in templates so `make css` can see them. An icon-only control has a tooltip. A labeled button does not repeat its label in a tip.
- **Import page.** Scan and import stay available; Match can create a series. On Import, **Mark new videos as ignored** is checked and disabled. Page help says to index with that on before matching files. File matching is a collapse under the header (ordered auto-match: series uniqueid / title / folder name, then video remote id / title / series-from-folder). The toolbar starts with **Reset and rescan** (same default `btn` size as **Import**; inbox only; no folder picker or path label). The shell paints immediately, then the match catalog and one inbox scan run in parallel unless an `import` or `import_plan` task is already queued or running. Leaving the page drops those fetches with no error toast. While any of those tasks is open, the candidate list is a spinner plus a link to Tasks, and Reset and rescan and bulk Import stay disabled until the queue drains (live; **Import now** shows the busy shell at once; the last import auto-rescans). Scanning while imports are open returns a conflict. The file list waits on the scan; Match waits on the catalog. Long scans are not cut off by the usual request timeout. Candidates are a vertical list, one item per stem group (case-insensitive; `[id]` stripped so sidecars still merge), plus sidecar-only attach groups and other non-importable files. Media under a `tvshow.nfo` tree nests in one series-folder row (`tvshow.nfo` path plus series art; those meta files are not separate candidates). Each importable row: files and match note on the left, status and Match or Unmatch on the right. Unmatch clears the pick. No series or video summary text on the row. The path is primary with a role icon (truncates with ellipsis when tight); extra sidecars stay visible as a count plus role icons (basename tips). Short status on the right of that file line: Matched, New, unmatched, or block reason (duplicate episode claim / duplicate create remote id). tvshow.nfo folder rows use the same path line layout (path truncates before sidecar count/icons move) with Matched or unmatched on the right. Scan auto-match text does not include the remote id. An empty scan is an alert. No scan status line and no incomplete-full-scan warning on this page. A divider sits above the toolbar: **Reset and rescan** (default `btn` size, clears every pick then scans again), **Show only unmatched** (warning and error rows: unmatched, duplicate episode claim, duplicate create remote id; success rows hidden), and **Import** on the right (wraps when tight; label `Import (matched/total)` for media; no animation). Load and **Reset and rescan** scan the import folder; Reset and rescan clears matches (daisyUI confirm modal when the operator has manual picks). **Reset and rescan** toasts how many auto matches were found; the first load stays quiet. The candidate list is a nested inbox tree rooted at the import path (label `/import/`), drawn as a flat list with a continuous CSS left rail for depth. Every directory row shows the path segment relative to its parent (root keeps `/import/`; trailing `/`; a `tvshow.nfo` tree appends `tvshow.nfo` on that path and lists series art as sidecars). Leaf file paths are relative to the parent folder row. A directory with exactly one media/sidecar group and no `tvshow.nfo` is omitted; the file line keeps that folder segment in its relative path. Every directory row (including the root) has a series join at half row width (same share as one leaf match join); picking a series auto-selects that folder and descendant folders/media, including over a descendant `tvshow.nfo` auto-select (child joins stay editable and can rematch). A `tvshow.nfo` tree auto-selects its matched or draft series on that folder and every nested folder under it; series and episode joins stay editable. Empty directories are omitted; successive dirs with no media and no `tvshow.nfo` collapse into one path row (e.g. `/import/Show/a/x/sd/`); folders stay expanded. Each importable leaf has inline searchable series and video joins sharing the row 50/50 (poster/thumb rows; episode pick list shows series title then status; join trigger is title only), series and episode filters offer Create when no match; clear is a small X inside the pick trigger when a value is selected. Series catalog loads once; episode lists fetch on open/search (capped; no full-library dump). The leading icon on the file line is the role icon (video / sidecar), not match status. Every folder and leaf row has a rounded box: neutral border for plain folders and non-importable files, warning or success fill for tvshow.nfo folder rows from the series pick, warning fill for unmatched media/sidecars, success fill when matched, error fill when two or more media rows claim the same indexed episode or two ready Create rows share a remote id. tvshow.nfo trees and folder picks auto-select series; joins stay editable. Create in a filter list applies immediately (no Add series / Add video modal); series needs a typed title; video uses the filter or suggested title and auto-fills upload date from the file when possible. Sidecar attach hides create series/video and only lists videos that already have packed media. Media lists packed videos (episode pick rows show series title then status); the episode picker hides videos already claimed by another media row, but scan can still seed the same episode on two files. Those duplicate claims stay visible in error tone until the operator clears or reassigns one. **Import** opens a summary. When any series draft exists (NFO and/or bare plus-series), steps are **Series** then **Videos**: step 1 lists editable titles plus shared root + quality (delivery/monitored defaulted); step 2 is the video tree. Confirm always posts `POST /api/import/confirm` → `import_plan`. Series and video Create are inline on Match; Series confirm still collects root and quality for drafts. Summary badges new series / new episode; warns when CREATE would use file mtime for upload date. Duplicate create remote ids disable Import. Episodes that replace packed library media are highlighted in the summary tree. When more than one ready file claims the same indexed episode, **Import** stays disabled with a tip until each video has only one media file (summary still blocks **Import now** as a safety net). When any item would override, the summary shows that the import will override already present files and requires **Override files for N episodes** before **Import now** is enabled. Footer: Cancel, optional Back/Next, primary **Import now**. Post-import integrity follows each series quality profile **File integrity** (no summary checkbox). An orphan `info.json` is listed only. A lone `.nfo` or thumb is listed only; beside a same-name video it is metadata or art. Applying an orphan or sibling updates editable metadata, then regenerates the episode NFO from the database.

- **UI labels in copy.** When hint, info, tooltip, flash, help, alert, or other operator-facing text names a page, nav item, button, control, setting, closed-set option, or status, wrap that exact label in ASCII single quotes (`'Import'`, `'Reset and rescan'`, `'Mark new videos as ignored'`, `'Settings → Queue / Domains'`). One pair around a multi-word label. Do not use bold or backticks for those labels in UI strings. Ordinary English stays unquoted. This file may still use bold for layout. - **List rows.** Optional select, media, title line (kind, warning, task), second line, optional progress, optional actions. Series list rows keep the circular poster; when a banner exists it is right-aligned at full row height (intrinsic width) with a dark fade starting at the banner's left edge. Headphones badge only for audio. Video placeholders use a play icon; packed media and a single-video source use a film icon. A feed uses a list icon; 'Mark new videos as ignored' shows as Discovered Ignored under the title (list) or in the Discovered column (table), not on the kind icon.
- **Videos page.** `/videos` is the library-wide video list (Series unset = all videos). Same filter catalog as series videos plus optional Series. Default sort Date added (`id DESC`). Sort also offers Upload date, Acquired, Duration, Title. Modes list|cards|gallery|table. list|cards|gallery use **infinite** load (chunk 20); table uses **paginated** (page 10). Series title on every list/card row (and a Series column in table); Gallery title is a hover overlay on the thumb (no per-item row actions). Row actions on list match series videos (Want / Ignore / Delete); Card has no per-item row actions (bulk bar still works) and live-swap `#videos-list-live`. Multi-select matches series videos (Want / Ignore / Refresh sidecars / Edit metadata / Delete); the action bar shows in every view mode; confirm policy is **Bulk confirm** (Want / Ignore / Refresh / Clear errors one-shot; Delete and Edit metadata always modal); Select all uses `GET /videos/ids` with the current filter; bulk POSTs redirect back to `/videos` preserving filters.
- **Series list.** list|cards|gallery **infinite** (chunk 20); table **paginated** (page 10). Status filter: monitored, unmonitored, complete, incomplete, has errors. Complete and incomplete use list progress: downloaded over downloaded plus open work (wanted, archive wait, download error, integrity failure). Incomplete includes those errors. Has errors is video errors and/or a source scan error. The bar is downloaded, then errors, then wanted (wanted has no fill; track shows through). An unmonitored series mutes the whole bar and its labels. The label under the bar omits zero counts and names each non-zero segment (`N downloaded`, `N errors`, `N wanted`); the label grid is 1/2/3 columns to match how many are shown. The same bar sits on the series Videos header. The second line is root - quality (omits the root when only one exists; quality shows as best for audio). A health badge appears only for a problem, in order: download error, integrity failure, source scan error, full scan incomplete with no schedule. Error badges include a count. Running tasks do not use this badge. Multi-select is sticky across filter swaps and infinite appends, hides row checkboxes until on, drops the title underline, and keeps the monitor control visible but disabled. The bar shows `N/M selected`, **Select all** when more matching rows remain than are loaded, and Edit, Edit metadata, icon-only Monitor / Unmonitor, and Delete (disabled until something is selected; confirm policy is **Bulk confirm**). A busy bulk edit locks the bar. Default sort Title; Sort also offers Date added, Last upload, Downloaded, Wanted, Errors, Size (counts, last upload, and packed size default desc). Table Columns can show Size (sum of packed video `files.size_bytes`). View list|thumbs|table.
- **Source status.** One Status column: icon and a short label. Priority: running, pending, scan error, stalled or incomplete, then indexed or no schedule. Incomplete with a schedule is a warning and does not escalate to the series; the tip says the full scan is incomplete and when the next scan is. Incomplete with no schedule is an error and does escalate. Both tips mention regexp filters when title filters are set. A finished single says complete (`calendar-check-2` success). A scheduled feed shows the last-scan summary (`calendar-clock` success); schedule off says disabled (`calendar-minus` muted) so it is distinct from feeds with a future tip scan. Scan-error label and tip use the error code (or a short fallback), schedule/limit, and 'Open task for full error' when a task link exists; the full yt-dlp message stays on the task page. The tip can also mention a full-scan limit. List view pins Status to a fixed-width track with the icon in a 1.25rem column so icons stack. The cell updates live. Source detail does not repeat this in the page subtitle; last scan and last error are on the Status card.
- **Scroll.** Full-page pager and filter links restore scroll on the same path. A POST that redirects back to the current path does too, including Tasks actions. Opt out when a navigation should start at the top. A panel that already live-swaps should keep doing that instead of a full page load. Live list search/filter swaps pin the panel's viewport position (so typing in Search does not jump the page up when the panel height changes).
- **Series videos.** Hidden on series detail until the series has at least one indexed video. Always **paginated** (page 10) for list|cards|gallery|table because Notes/Files sit below. Pager above and below (table: Columns left of summary, top pager on the right). Upload From/To live under Filter → Upload date. Default sort Upload date. Sort also offers Date added, Acquired, Duration, Title. Modes list|cards|gallery|table; series title omitted (route-locked). Multi-select matches the series list. The action bar shows in every view mode. Row Want, Ignore, Download now, and Delete stay visible but disabled while multi-select is on. The bar can refresh sidecars, edit metadata, and run icon-only Want, Ignore, and Delete. Confirm policy is **Bulk confirm**. Delete accepts downloaded and missing only; other statuses are skipped and the flash says so. Bulk metadata edit locks the bar while it runs. Scan, bulk edit, and file delete refresh the list. With no sources and no videos, Sources omits the section header and shows: No videos yet. Start by adding a single video or a channel/playlist. Then the Add single video / Add channel/playlist pair.
- **Tooltips.** daisyUI tooltip only, never the native title. Do not put a tooltip on a flex row or a table cell; wrap a child. Keep an existing accessible name. Do not fade a tooltip host. Tips stay short; long errors and yt-dlp text live on the linked task or detail page. List-table wraps scroll sideways (sticky columns) and clip tips that paint outside the wrap. Trailing action tips use `tooltip-left` (Sources Scan / Full scan / Edit / Delete; Files Check integrity / Delete; video Want·Ignore·Clear error·Delete) so they open inward. Keep tips short. Hovered tips paint above list chrome. Inside a join, the tip stays on the joined control.
- **Files multi-select.** Browser Files, series-detail Files, and video-detail Files share multi-select (toolbar or embed toggle). The bar shows `N/M selected`, **Select all** via `GET /files/ids` with the current filter/scope, **Check integrity**, and **Delete**. Row Check integrity / Delete stay visible but disabled while multi-select is on. Confirm policy is **Bulk confirm** (Check integrity one-shot; Delete always confirms). Bulk Check skips NFO, missing, and already-queued rows; bulk Delete only removes deletable sidecars (`sub` / `thumb` / `other`) and skips the rest (flash includes skipped count). When `#files-list-live` is on screen, SSE `task.done` / `task.failed` (and throttled `task.updated`) for `file_hash_check`, `integrity_check`, `integrity_check_initial`, and `sync_files` HTMX-refresh the panel so Integrity status and queued Check state update without a full reload.
- **Video detail.** Media and details sit side by side, same idea as task Stages and Details. Media is the packed file with a poster when there is a thumb, or a still image plus audio for audio delivery, or empty. Known resolution, frame rate, container, and duration sit under the player. Details are status and metadata, no separate thumb row. Status shows the task indicator, a short human status label, and, when a non-integrity task is open, a Queued or Running prefix and a link to the task. Otherwise an error status links out for details. Per-file integrity lives on the Files Explorer (list view: fixed-width status column before actions so shield icons stack; table: Integrity column; Size stays table-only) and each file detail page as icon + short label: `OK` / `Failed` (`shield-check` / `shield-x`; tip: last checked since, ISO date when older than 7 days - same as `rel_time` display), `Unchecked` (`shield-question`; applicable, never checked), `N/A` (`shield-off`; NFO), `Inactive` (`shield-ban`; missing file). File detail Details also lists **Last checked** and, when Failed with a prior OK, **Last OK** as separate rows; not on video Details. **Files** is the scoped Files Explorer (`video_id`) with table columns Type / File / Path / Integrity / Size / Acquired (plus Series/Video after Size when not scoped; Integrity default on, before Size), Filter Type plus Status (`failed` / `ok` / `unchecked` / `inactive` / `na` matching the Integrity column labels), Sort Acquired|Size|Path|Type (no Series sort), Check integrity (NFO disabled), Delete always shown (disabled with tip when not allowed), and multi-select as above. **Notes** sit full width between Details and Files (always visible): operator-only textarea, autosave after four times the list-filter search pause (and on blur / link leave / `pagehide` via keepalive so a leave before the pause still saves); save confirms with a top-right flash toast; not written to NFO or packed files; 64 KiB max. History is a vertical timeline, newest first. Rows that share a task nest under that task, substages newest first. Discover and update projections stay their own nodes. Registered files open a preview. Subtitle, thumb, and other files can be deleted. Media, NFO, info.json, and SponsorBlock cannot.
- **Series detail.** Navbar has Edit series, Edit metadata, Monitor/Unmonitor (`btn btn-square` outline bookmark, no green fill), and Delete. **Notes** sit above Files (always visible; same autosave and cap as video Notes). Sources and Videos stay above Notes. Sources on series detail are a plain list (no Filter / Sort / View bar; always list view, all sources on the series) via `/explorer/browse?type=sources&series_id=…` for live refresh; Browser Sources keep the full Explorer toolbar and the same row actions (Scan / Full scan / Edit / Delete). Both share multi-select (toolbar or embed toggle): bar shows `N/M selected`, **Select all** via `GET /sources/ids`, **Scan**, and **Delete**. Row Scan / Full scan / Edit / Delete stay visible but disabled while multi-select is on. Confirm policy is **Bulk confirm** (Scan one-shot, modal title `Scan N sources`; Delete always confirms; checkbox reads `Delete N downloaded and M indexed videos` from `GET /sources/delete-impact`). Bulk Scan skips already-queued or ineligible rows; bulk Delete hard-deletes each source and its videos (flash includes skipped count). **Files** is the scoped Files Explorer (`series_id`: series-meta plus all episode files) so hard series integrity rollup has one place to see every failing row; multi-select matches Browser Files. Import (null-source videos) stays a pinned row below the Explorer when present (whole row filters Videos to `source=import` via HTMX and scrolls to the Videos panel). Add channel/playlist and Add single video stay on the section header.
- **Series files.** Same gate as Videos: hidden until the series has at least one indexed video. The series folder table lists `tvshow.nfo` and art when present. Names open a preview.
- **Metadata.** Series and video metadata share one library-wide suggestion list per field (studio, genres, tags, country, content rating, actor name, actor role). Content rating also seeds the US TV ratings. Genres, tags, and actors are ordered lists (index, move, remove) except where reorder is off (subtitle languages are chips). Creatorr-managed genre or tag rows have no remove or reorder. See [`download-and-library.md`](download-and-library.md). Subtitle language suggestions start with `all`, then common tags. Categories→genres and yt-dlp tags→tags SoftFill are always on; domain reaches videos via source default tags SoftFill. Video Metadata includes a **Special kind** select (`none` = regular / SQL NULL / Special episode / feature kinds; `none` is muted) with field help under the control; series video bulk Edit metadata uses a No-change select for the same values and never prefills Special kind (operator must pick a value to change it); series video rows show a pack-role badge. Settings → Library root has three format fields (Episode / Special episode / Special feature) with JoinPrefix chrome on Episode format only. Web Archive fallback lives under Settings → Queue / Domains.
- **Source filters.** Feeds group full-scan limit and title include/exclude under **Filter**, with the line that only matching videos are indexed. **Discovered video status** is Wanted or Ignored. On Import, add-series locks that to Ignored. Singles do not show these fields.
- **Series settings.** Add, Edit, and bulk Edit share one field set: title (hidden in bulk), delivery, root, and quality profile. Monitored is a navbar / list / bulk action (not a settings field); new series start monitored. Bulk has a No-change option and pre-fills fields that agree. Edit locks title and root while a download, SponsorBlock cut, initial integrity check, series-scoped episode rename, or `series_move` for that series is open. Saving a title or root change flashes that a folder move is queued; the fields stay unchanged until the move finishes. Download now and path-affecting video Metadata Save are refused with an error while a `series_move` is open. Audio disables the quality profile and says audio uses the best available quality.
- **Metadata fetch.** The URL and Fetch are one join. Fetch fills the form only. Save writes the library. Cancel drops the draft. Video defaults to the source URL. The Fetch URL field is not HTML-`required` on ephemeral prefetch (empty submit stays operator-clear). The thumbnail slot appears once the video is packed. **Refresh sidecars** rewrites thumb, subtitles, and NFO from the source and never rewrites `info.json`. **Download now** is hidden when the video is already downloaded. **Want** on an unmonitored series sets status only and flashes that download is not queued until the series is monitored.
- **Footer.** Version, `docker` or `binary`, and short commit when known. Omit an unknown revision token when the bake has no sha.
- **Modals.** Close only from Cancel or another explicit action, not from the backdrop. Cancel resets the form, restores art previews, and restores list chips. Closing without Cancel keeps what was typed. Clearing art hides the preview; a new file shows it again.
- **Flash.** Success, warning, and error are toasts under the navbar, not banners. They dismiss themselves and leave the URL. Field errors use the validator. Add series and Add video keep an in-modal alert only for errors that do not belong to a control. Success opens the new series, except Import match, which stays and locks that series.
