# UI (HTMX + daisyUI)

Index: [README.md](README.md). Agent contract: [`AGENTS.md`](../AGENTS.md).

**CSS.** Tailwind 4 + daisyUI 5. Source: [`internal/web/ui/src/input.css`](../internal/web/ui/src/input.css) → committed [`internal/web/static/app.css`](../internal/web/static/app.css). `make css` also bundles JS with esbuild (ES modules in [`internal/web/ui/src/js/`](../internal/web/ui/src/js/) -> committed `internal/web/static/app.js`; the import page script `src/js/import.js` -> `static/import.js`) and vendors ECharts and Lucide. Edit the sources, never the bundles. Keep a Go-guarded comment as `//!` (esbuild drops other comments). After class or vendor bumps, run `make css`. Themes: curated daisyUI set on Settings → General **Appearance** (Dark / Light / Special); default follows OS (`emerald` / `dark`); override is this browser only (`localStorage` key `creatorr-theme`).

**Dev UI reload:** `CREATORR_WEB_DEV=1` (optional `CREATORR_WEB_DIR`, default `internal/web`) reloads templates and static files each request. Compose mounts `./internal/web` at `/web`. CSS still needs `make css`.

**Document title:** the browser tab is always `Creatorr`. In-page headers still use the page title.

**daisyUI first.** Stock daisyUI + Tailwind in markup, or daisy theme tokens. Prefer a different HTML pattern over custom CSS. A small glue fix (overflow, stacking, clip) belongs in `input.css` with a one-line why. Do not add another UI kit. A large or unclear fix: stop and ask.

Glue already in `input.css` (the why, not the selectors):

- Modal tips must paint outside the box, so the overlay scrolls and the box does not clip. Modals sit above the shell navbar. Tall previews without tips scroll inside the box.
- The bell menu and flash toasts sit above open modals. Toasts sit below the navbar so they do not cover the bell.
- Import list and summary tips rise above the next row on hover.
- Genre, tag, and actor rows number themselves so reorder does not need JS.
- Filter date fields stay transparent and wide enough that the browser control does not look nested.
- List-view toolbar is one join: search + `q_field` + Filter / Sort / View. Filter/Sort/View wrappers use `.input.join-item` (same field chrome as search; borderless triggers; no nested `btn join-item`). Menus use `dropdown-bottom dropdown-end` (open below, end-aligned) with roomy widths (Filter `w-80`, Sort `w-64`, View `w-52`). Sort shows direction on the selected option (up/down arrow); re-selecting that option toggles `dir=asc|desc` (field default when omitted).
- Validators show error only. A valid field stays neutral, including after Save on an empty optional field.
- Long format-selector tips stay one monospace line.
- A bulk-selected list row is square so the selection fill covers it.
- A radio join highlights the checked choice.
- The app column is at least the `md` width so page padding does not jump; narrower viewports scroll sideways.
- Configurable list tables (`[data-list-table]`) scroll sideways in the wrap; Title (and select when shown) stick left, Actions stick right on video tables. A page summary and columns settings sit above the wrap so the columns menu is not clipped.

**Icons.** [Lucide](https://lucide.dev). Recreate icons on load and after HTMX swaps.

**Nav.** Series, Videos, Tasks, Import, History, Stats, Settings. Brand **Creatorr** goes to Overview. Overview shows library stats, then **Running tasks** while any task is running (all domains, kind links to the task, no Cancel), then **Recent additions**: locked thumbs glance of newest downloaded videos (acquired order, series title on each card, no Filter / Sort / View chrome, no row actions). Full open video browsing is **Videos** (`/videos`).

Shell is one centered column. Below the `md` width the column scrolls sideways instead of reflowing. Small screens get a hamburger; wide screens get a horizontal menu. The end of the bar is the bell (latest four in-app notifications, unread rows marked, **Mark all as read**, **View all**, badge for unread alerts and warnings) and the user menu (name + **Log out**). Footer: version, `docker` or `binary`, short commit (links to GitHub when it is a sha), and the repo link. Settings is a submenu (General, Library, Connect, Queue / Domains, Scheduler, Maintenance) and does not stay open after navigation. Series shows an error count when any series has a video error or a source scan error (hides at zero). Tasks shows an open-task count (all host lanes, including soft-paused). Soft-pause alone does not add a nav badge; the lane chip shows Paused. Task detail is `/task/{id}`: **Stages** beside **Details** (outcome keys and per-video lists), **Commands** full width when present, **Logs** under that. The log pane scrolls to the bottom on load and on Refresh. Stages always include **enqueued**; a single-video task uses that video's history; otherwise **started** comes from `started_at`. Finished tasks end with **done**, **failed**, or **cancelled**. Duration is the gap from the previous row (largest unit, omit a second or less). History has a shared **From** / **To** range, then **Notifications** (opening the page marks unread alerts and warnings read; filter by level) then **Tasks** (filter by domain, kind, status). Notification rows open `/notification/{id}` (title, level, message, related task and videos; opening marks an unread alert or warning read). Task rows open the task. Task history columns are Domain, Kind, When, Message (failed rows prefer a short root-cause line from the task error when the stored message is generic). Error code and detail JSON stay on the task page.

**Reuse first.** Compose from `internal/web/templates/` and `internal/web/partials/`. Repeated chrome becomes a shared partial.

## Patterns

- **Chrome.** One treatment per role. Primary is the main commit (Save, Add, verify-import). Secondary is a second add beside a primary add. Outline is a labeled page-navbar action. A plain button is an icon-only action that is not destructive, and modal Cancel / Keep. Soft error is a delete trigger; the confirm submit is solid error. A settings-list delete that is not joined to Edit is a ghost button with error text. Muted is for empty or inherited values and for disabled label text. Mute the text, not a tooltip or anything that wraps one (opacity fades the tip). daisyUI already fades a disabled checkbox; do not fade it again. Warning means paused or recoverable, error means failed or blocked, success means healthy or complete. An active list filter uses the primary field color. A disabled control does not receive hover, so put the tip on a wrapper (inside a join, `aria-disabled` on the button instead, so the seam stays one control). Tailwind class names must appear whole in templates so `make css` can see them. An icon-only control has a tooltip. A labeled button does not repeat its label in a tip.
- **Import page.** Scan and import stay available; Match can create a series. On Import, **Mark new videos as ignored** is checked and disabled. Page help says to index with that on before matching files. File matching is a collapse under the header (ordered auto-match: series uniqueid / title / folder name, then video remote id / title / series-from-folder). The toolbar starts with **Reset and rescan** (same default `btn` size as **Import**; inbox only; no folder picker or path label). The shell paints immediately, then the match catalog and one inbox scan run in parallel unless an `import` or `import_plan` task is already queued or running. Leaving the page drops those fetches with no error toast. While any of those tasks is open, the candidate list is a spinner plus a link to Tasks, and Reset and rescan and bulk Import stay disabled until the queue drains (live; **Import now** shows the busy shell at once; the last import auto-rescans). Scanning while imports are open returns a conflict. The file list waits on the scan; Match waits on the catalog. Long scans are not cut off by the usual request timeout. Candidates are a vertical list, one item per stem group (case-insensitive; `[id]` stripped so sidecars still merge), plus sidecar-only attach groups and other non-importable files. Media under a `tvshow.nfo` tree nests in one series-folder row (`tvshow.nfo` path plus series art; those meta files are not separate candidates). Each importable row: files and match note on the left, status and Match or Unmatch on the right. Unmatch clears the pick. No series or video summary text on the row. The path is primary with a role icon (truncates with ellipsis when tight); extra sidecars stay visible as a count plus role icons (basename tips). Short status on the right of that file line: Matched, New, unmatched, or block reason (duplicate episode claim / duplicate create remote id). tvshow.nfo folder rows use the same path line layout (path truncates before sidecar count/icons move) with Matched or unmatched on the right. Scan auto-match text does not include the remote id. An empty scan is an alert. No scan status line and no incomplete-full-scan warning on this page. A divider sits above the toolbar: **Reset and rescan** (default `btn` size, clears every pick then scans again), **Show only unmatched** (warning and error rows: unmatched, duplicate episode claim, duplicate create remote id; success rows hidden), and **Import** on the right (wraps when tight; label `Import (matched/total)` for media; no animation). Load and **Reset and rescan** scan the import folder; Reset and rescan clears matches (daisyUI confirm modal when the operator has manual picks). **Reset and rescan** toasts how many auto matches were found; the first load stays quiet. The candidate list is a nested inbox tree rooted at the import path (label `/import/`), drawn as a flat list with a continuous CSS left rail for depth. Every directory row shows the path segment relative to its parent (root keeps `/import/`; trailing `/`; a `tvshow.nfo` tree appends `tvshow.nfo` on that path and lists series art as sidecars). Leaf file paths are relative to the parent folder row. A directory with exactly one media/sidecar group and no `tvshow.nfo` is omitted; the file line keeps that folder segment in its relative path. Every directory row (including the root) has a series join at half row width (same share as one leaf match join); picking a series auto-selects that folder and descendant folders/media, including over a descendant `tvshow.nfo` auto-select (child joins stay editable and can rematch). A `tvshow.nfo` tree auto-selects its matched or draft series on that folder and every nested folder under it; series and episode joins stay editable. Empty directories are omitted; successive dirs with no media and no `tvshow.nfo` collapse into one path row (e.g. `/import/Show/a/x/sd/`); folders stay expanded. Each importable leaf has inline searchable series and video joins sharing the row 50/50 (poster/thumb rows; episode pick list shows series title then status; join trigger is title only), series and episode filters offer Create when no match; clear stays a join square. Series catalog loads once; episode lists fetch on open/search (capped; no full-library dump). The leading icon on the file line is the role icon (video / sidecar), not match status. Every folder and leaf row has a rounded box: neutral border for plain folders and non-importable files, warning or success fill for tvshow.nfo folder rows from the series pick, warning fill for unmatched media/sidecars, success fill when matched, error fill when two or more media rows claim the same indexed episode or two ready Create rows share a remote id. tvshow.nfo trees and folder picks auto-select series; joins stay editable. Create in a filter list applies immediately (no Add series / Add video modal); series needs a typed title; video uses the filter or suggested title and auto-fills upload date from the file when possible. Sidecar attach hides create series/video and only lists videos that already have packed media. Media lists packed videos (episode pick rows show series title then status); the episode picker hides videos already claimed by another media row, but scan can still seed the same episode on two files. Those duplicate claims stay visible in error tone until the operator clears or reassigns one. **Import** opens a summary. When any series draft exists (NFO and/or bare plus-series), steps are **Series** then **Videos**: step 1 lists editable titles plus shared root + quality (delivery/monitored defaulted); step 2 is the video tree. Confirm always posts `POST /api/import/confirm` → `import_plan`. Series and video Create are inline on Match; Series confirm still collects root and quality for drafts. Summary badges new series / new episode; warns when CREATE would use file mtime for upload date. Duplicate create remote ids disable Import. Episodes that replace packed library media are highlighted in the summary tree. When more than one ready file claims the same indexed episode, **Import** stays disabled with a tip until each video has only one media file (summary still blocks **Import now** as a safety net). When any item would override, the summary shows that the import will override already present files and requires **Override files for N episodes** before **Import now** is enabled. Footer: Cancel, optional Back/Next, primary **Import now**. Post-import integrity follows each series quality profile **File integrity** (no summary checkbox). An orphan `info.json` is listed only. A lone `.nfo` or thumb is listed only; beside a same-name video it is metadata or art. Applying an orphan or sibling updates editable metadata, then regenerates the episode NFO from the database.
- **List / Add.** Existing rows are a table (`partials/list.html`). Add is a button that opens a modal. Edit is a per-row modal.
- **Source detail.** **Settings** and **Status** sit side by side at equal height. Settings is what Edit changes: URL (fixed after create), name, and for feeds the scan schedule, full-scan limit, title filters, and discovered video status. Edit (feed and single) also has a collapsed **Default video metadata** block (studio, country, content rating, genres, tags, actors, special kind) SoftFilled onto new videos; domain is always seeded into source tags on add (editable on feed, locked on single). Status is kind, tool, domain, last scanned, last error, and (when smart cookies is on with a jar) cookie policy / learning. On the series source row, Scan, Full scan, and Edit are icon-only. On source detail, Scan, Full scan, Edit, and Retry keep labels. Delete there is icon-only. Both scan buttons stay visible and disabled while a scan is queued for that source.
- **Notifications and settings chrome.** Settings → Connect leads with **Notifications**: a fixed in-app channel plus optional Apprise rows. Add defaults to **All**. Event choices are Alert / Warning / Info and **All** is exclusive with specifics. The Apprise URL is joined to **Test** (not written to History). The in-app channel is History plus the bell. Then the yt-dlp card (path, version, last checked, update channel, **Update now**; the schedule lives on Scheduler and gates boot and cron only). **arguments** has **player_client**. **plugins** lists packages, including bundled **yt-dlp-ejs**, and **fetch_pot**. Settings → General **Authentication**: change username or password (no current password; length 4 to 72) and an API key row (copy, regenerate) with a link to the OpenAPI document. **External services** shows the FlareSolverr and PO token URLs as disabled fields with a health icon, filled in after the page shell. **fetch_pot** stays disabled until the PO URL is set. **Appearance** is the theme picker, this browser only. Inline settings forms save on change or blur. Modals keep Save. The stats header says chart samples are kept for one year. Setup and login have no app shell. The user menu includes **Log out**.
- **Tasks.** Two intro lines: queues are per domain, and pause does not stop interactive metadata prefetch. Each host lane title is the domain (warning when paused), then limit chips when the lane has open or scheduled work (same order as the Domain override form; rate in binary units; a host override is full strength and a default is muted), then queue status left of History: **Paused** (warning; busy slide and a tip while tasks still run; quiet label when nothing is open), **Cooldown** (fill counts down; do not flip to Idle at zero if rows are still active), **Idle** (empty; quiet label when nothing is open), **Active** (busy slide, free parallel slots), **Busy** (busy slide, max parallel reached). **Cancel all pending** sits just right of that status. The `system` lane is a title only. Open tasks are one list, running first, 10 per page, with a query key per lane so paging one host does not page the others. Scheduled `system` rows stay above that list. An empty lane has no empty-state alert. Pending progress is empty (warning while the lane is paused). Mid-run progress is determinate. A running task at 0%, 100%, or with no number is an indeterminate busy slide, updated in place so the animation does not restart. Task detail uses the same status and bar in the header. Download progress is per format, with throughput when yt-dlp reports it. Cookie fallback says when the attempt is without cookies, when it retries with cookies, and when cookies or a PO token were used, nested under that attempt. A re-encode cut and an integrity null-decode map time onto 0-1. Remux, pack, and copy-cut are a message only. A failed task shows the error code and cleaned yt-dlp error text. The notify label for `ytdlp_failed` is **yt-dlp failure**. A `rename_episodes` task lists renames (or a dry-run plan while still running). An integrity task shows ok / partial / skipped / failed, then failed videos only (capped).
- **Status badge.** Icon plus tooltip, same warning / error / success meaning as other status. History and task-detail chips use the shared partial. Live updates must keep using that partial.
- **Maintenance.** Settings → Maintenance: action checkboxes (Apply episode format, Regenerate all NFO files, File sync, Integrity check, Refresh sidecars; a busy system action shows queued and stays disabled), scope (whole library or one or more series via an inline series dropdown; chosen series sit in a list above the picker with remove; clears after Run), **Preview renames** (only with Apply episode format; dry-run, cap 500), and **Run selected**. Confirm lists actions, scope, packed count, and warns when Refresh sidecars will contact source sites. File sync ignores scope and is also a Scheduler job. Integrity check and Refresh sidecars match the single-video actions, scoped. Checkboxes unlock when the system task finishes; the selection survives that refresh until Run.
- **Roots and quality profiles.** Table plus Add modal; rows edit and delete. Delete confirms when unused and is disabled with a used-by tip when assigned. An invalid root path keeps the modal open and marks Path. The profile list is alphabetical. The name tip is the format selector, one line.
- **UI labels in copy.** When hint, info, tooltip, flash, help, alert, or other operator-facing text names a page, nav item, button, control, setting, closed-set option, or status, wrap that exact label in ASCII single quotes (`'Import'`, `'Reset and rescan'`, `'Mark new videos as ignored'`, `'Settings → Queue / Domains'`). One pair around a multi-word label. Do not use bold or backticks for those labels in UI strings. Ordinary English stays unquoted. This file may still use bold for layout. Quote exact operator wording.
- **Fields.** Shared field partials: the info tip sits by the label, not joined to the control. A join may add a non-editable prefix or suffix (episode format shows the series folder and extension). Invalid fields use the daisyUI validator; the hint is hidden until invalid. On a join, the validator wraps the join so the hint still lines up. A grouped section is a fieldset with a background and border. A disabled control keeps its value in a hidden input, puts the reason tip on a wrapper, and mutes the label and hint only. A disabled checkbox mutes the label and uses the tip for why it is disabled (DisabledTitle, else Hint). A separate Hint stays muted under the control when set (purpose copy).
- **Scan schedule.** Shared cron join: field plus **enabled**. Off shows `never` and does not submit a schedule. Turning it back on restores this visit's value, else the field default. Scan defaults to `@weekly`. Free-form cron and the named presets stay available. The hint under a source schedule is about upload cadence, not the Scheduler page.
- **Empty values.** List cells use ASCII `-`, or a muted word such as never, none, or default. A detail row mutes the value only and uses those words, not `-`.
- **List filters.** Library lists (`/series`, `/series/{id}` videos, `/videos`) share one toolbar: search (placeholder `Search by...`; field via `q_field`) + `q_field`, a **Filter** dropdown (vertical accordion per field; a choice or date change applies immediately; no Apply button; genre/tag/actor rows toggle like other value links; value rows show the bare value; Has/No are small buttons on the category summary, right-aligned), Sort (selected option shows asc/desc with an up/down arrow; choosing that option again flips `dir`; title defaults asc, date-like sorts default desc), and View (`list` | `thumbs` | `table`). Table view shows essential columns by default; above the table a muted summary (range and total for the filtered page) sits left of the columns settings control (cookie per list; at least one column stays visible). Wide tables scroll sideways in the wrap; Title (and select when shown) stick left, Actions stick right on video tables. Active filters are a daisyUI [filter](https://daisyui.com/components/filter/) row under the bar (checked `btn` chips; uncheck removes that constraint; search text is not a chip - it stays in the search field). **Clear all** is a square `×` on the right of that row and shows when there are two or more chips (drops operator filters and search; sort, dir, and view stay). Locked route fields are omitted from the menu, chips, and row chrome (no Series control on a series page). Presence uses `empty=` / `not_empty=` (chip copy like `Has genre` / `No upload date`), offered under each field in the Filter menu. Facet options stay open (distinct values in series or library scope; other active filters do not shrink the list). One free-text search only. View is in the URL when not the default `list`; bare visits read `creatorr_mode_series`, `creatorr_mode_series_videos`, or `creatorr_mode_videos`. History and Tasks still use the older `list_filters` bar until they become presets of the same shell; Sources lists follow later the same way.
- **List filters (History / Tasks).** One join: optional search, optional date, optional selects. No leading Filter label. A select or date submits on change; search submits after a short pause in typing (and on blur). Hide a select with fewer than two options (History keeps domain and kind even when empty). History notifications filter by level; history tasks by domain, kind, origin, and status. History pages are 20 rows. The history range is From / To plus a clear control that matches those fields. Live lists swap in place.
- **Filter bar.** Checkbox chips. Hide when fewer than two options. Empty means show all. Prefer the shared list-view toolbar for new library lists.
- **List rows.** Optional select, media, title line (kind, warning, task), second line, optional progress, optional actions. Series rows use a circular poster and a headphones badge only for audio. Video placeholders use a play icon; packed media and a single-video source use a film icon. A feed uses a list icon, warning-colored when new videos are marked ignored.
- **Videos page.** `/videos` is the library-wide video list (Series unset = all videos). Same filter catalog as series videos plus optional Series. Default sort Date added (`id DESC`). Sort also offers Upload date, Acquired, Duration, Title. Modes list|thumbs|table. Series title on every row/card (and a Series column in table). Row actions match series videos (Want / Ignore / Delete) and live-swap `#videos-list-live`. Multi-select matches series videos (Want / Ignore / Refresh sidecars / Edit metadata / Delete); the action bar shows in every view mode; Want / Ignore / Refresh / Clear errors confirm only when more than 5 are selected (≤5 submit immediately); Delete and Edit metadata always open a modal; Select all uses `GET /videos/ids` with the current filter; bulk POSTs redirect back to `/videos` preserving filters.
- **Series list.** Page size 20. Status filter: monitored, unmonitored, complete, incomplete, has errors. Complete and incomplete use list progress: downloaded over downloaded plus open work (wanted, archive wait, download error, integrity failure). Incomplete includes those errors. Has errors is video errors and/or a source scan error. The bar is downloaded, then errors, then wanted (wanted has no fill; track shows through). An unmonitored series mutes the whole bar and its labels. The label under the bar omits zero counts and names each non-zero segment (`N downloaded`, `N errors`, `N wanted`); the label grid is 1/2/3 columns to match how many are shown. The same bar sits on the series Videos header. The second line is root - quality (omits the root when only one exists; quality shows as best for audio). A health badge appears only for a problem, in order: download error, integrity failure, source scan error, full scan incomplete with no schedule. Error badges include a count. Running tasks do not use this badge. Multi-select is sticky across filter swaps, hides row checkboxes until on, drops the title underline, and keeps the monitor control visible but disabled. The bar shows `N/M selected`, **Select all** when there is another page, and Edit, Edit metadata, and Delete, disabled until something is selected. A busy bulk edit locks the bar. Monitor is part of Edit, not a separate list action. Default sort Title; Sort also offers Date added, Last upload, Downloaded, Wanted, Errors (counts and last upload default desc). View list|thumbs|table.
- **Source status.** One Status column: icon and a short label. Priority: running, pending, scan error, stalled or incomplete, then indexed or no schedule. Incomplete with a schedule is a warning and does not escalate to the series; the tip says the full scan is incomplete and when the next scan is. Incomplete with no schedule is an error and does escalate. Both tips mention regexp filters when title filters are set. A finished single says complete. A scheduled feed shows the last-scan summary; schedule off says disabled, with the last scan still in the tip. The tip can also mention a full-scan limit. The cell updates live. Source detail does not repeat this in the page subtitle; last scan and last error are on the Status card.
- **Scroll.** Full-page pager and filter links restore scroll on the same path. A POST that redirects back to the current path does too, including Tasks actions. Opt out when a navigation should start at the top. A panel that already live-swaps should keep doing that instead of a full page load.
- **Series videos.** Hidden on series detail until the series has at least one indexed video. Pager only below the list. Upload From/To live under Filter → Upload date. Default sort Upload date. Sort also offers Date added, Acquired, Duration, Title. Modes list|thumbs|table; series title omitted (route-locked). Multi-select matches the series list. The action bar shows in every view mode. Row Want, Ignore, Download now, and Delete stay visible but disabled while multi-select is on. The bar can refresh sidecars, edit metadata, and run icon-only Want, Ignore, Download now, and Delete. Want / Ignore / Refresh sidecars / Clear errors confirm only when more than 5 are selected (≤5 submit immediately); Delete and Edit metadata always open a modal. Delete accepts downloaded and missing only; other statuses are skipped and the flash says so. Bulk metadata edit locks the bar while it runs. Scan, bulk edit, and file delete refresh the list. With no sources and no videos, Sources omits the section header and shows: No videos yet. Start by adding a single video or a channel/playlist. Then the Add single video / Add channel/playlist pair.
- **Tooltips.** daisyUI tooltip only, never the native title. Do not put a tooltip on a flex row or a table cell; wrap a child. Keep an existing accessible name. Do not fade a tooltip host. List tables scroll with the page so a tip is not clipped. Inside a join, the tip stays on the joined control.
- **Video detail.** Media and details sit side by side, same idea as task Stages and Details. Media is the packed file with a poster when there is a thumb, or a still image plus audio for audio delivery, or empty. Known resolution, frame rate, container, and duration sit under the player. Details are status and metadata, no separate thumb row. Status shows the task indicator, a short human status label, and, when a non-integrity task is open, a Queued or Running prefix and a link to the task. Otherwise an error status links out for details. The next row is file integrity: off (no media, or the profile has it off), eligible (profile on, no hash yet), hashed (hash, no schedule), monitored (hash and a schedule), or failed. An open integrity task, including a library check that covers this video, links beside the chip with the same Queued or Running prefix. The tip names the state and, when this media has been checked, when. The chip is this page only and does not live-update. **Notes** sit full width between Details and Files (always visible): operator-only textarea, autosave after four times the list-filter search pause (and on blur / link leave / `pagehide` via keepalive so a leave before the pause still saves); save confirms with a top-right flash toast; not written to NFO or packed files; 64 KiB max. History is a vertical timeline, newest first. Rows that share a task nest under that task, substages newest first. Discover and update projections stay their own nodes. Files are the media, then stem-matched companions (NFO, info.json, thumb, subs, SponsorBlock, other). Registered files open a preview; orphans do not. Subtitle, thumb, and other files can be deleted. Media, NFO, info.json, and SponsorBlock cannot.
- **Series detail.** **Notes** sit above Files (always visible; same autosave and cap as video Notes). Sources and Videos stay above Notes.
- **Series files.** Same gate as Videos: hidden until the series has at least one indexed video. The series folder table lists `tvshow.nfo` and art when present. Names open a preview.
- **Metadata.** Series and video metadata share one library-wide suggestion list per field (studio, genres, tags, country, content rating, actor name, actor role). Content rating also seeds the US TV ratings. Genres, tags, and actors are ordered lists (index, move, remove) except where reorder is off (subtitle languages are chips). Creatorr-managed genre or tag rows have no remove or reorder. See [`download-and-library.md`](download-and-library.md). Subtitle language suggestions start with `all`, then common tags. Categories→genres and yt-dlp tags→tags SoftFill are always on; domain reaches videos via source default tags SoftFill. Video Metadata includes a **Special kind** select (`none` = regular / SQL NULL / Special episode / feature kinds; `none` is muted) with field help under the control; series video bulk Edit metadata uses a No-change select for the same values and never prefills Special kind (operator must pick a value to change it); series video rows show a pack-role badge. Settings → Library root has three format fields (Episode / Special episode / Special feature) with JoinPrefix chrome on Episode format only. Web Archive fallback lives under Settings → Queue / Domains.
- **Source filters.** Feeds group full-scan limit and title include/exclude under **Filter**, with the line that only matching videos are indexed. **Discovered video status** is Wanted or Ignored. On Import, add-series locks that to Ignored. Singles do not show these fields.
- **Series settings.** Add, Edit, and bulk Edit share one field set: title (hidden in bulk), delivery, monitored, root, and quality profile. Bulk has a No-change option and pre-fills fields that agree. Edit locks title and root while a download, SponsorBlock cut, initial integrity check, series-scoped episode rename, or `series_move` for that series is open. Download now and path-affecting video Metadata Save are refused with an error while a `series_move` is open. Audio disables the quality profile and says audio uses the best available quality.
- **Metadata fetch.** The URL and Fetch are one join. Fetch fills the form only. Save writes the library. Cancel drops the draft. Video defaults to the source URL. The Fetch URL field is not HTML-`required` on ephemeral prefetch (empty submit stays operator-clear). The thumbnail slot appears once the video is packed. **Refresh sidecars** rewrites thumb, subtitles, and NFO from the source and never rewrites `info.json`. **Download now** is hidden when the video is already downloaded. **Want** on an unmonitored series sets status only and flashes that download is not queued until the series is monitored.
- **Footer.** Version, `docker` or `binary`, and short commit when known. Omit an unknown revision token when the bake has no sha.
- **Modals.** Close only from Cancel or another explicit action, not from the backdrop. Cancel resets the form, restores art previews, and restores list chips. Closing without Cancel keeps what was typed. Clearing art hides the preview; a new file shows it again.
- **Flash.** Success, warning, and error are toasts under the navbar, not banners. They dismiss themselves and leave the URL. Field errors use the validator. Add series and Add video keep an in-modal alert only for errors that do not belong to a control. Success opens the new series, except Import match, which stays and locks that series.
