# UI (HTMX + daisyUI)

Index: [README.md](README.md). Agent contract: [`AGENTS.md`](../AGENTS.md).

**CSS.** Tailwind 4 + daisyUI 5. Source: [`internal/web/ui/src/input.css`](../internal/web/ui/src/input.css) → committed [`internal/web/static/app.css`](../internal/web/static/app.css). `make css` also bundles JS with esbuild (ES modules in [`internal/web/ui/src/js/`](../internal/web/ui/src/js/) -> committed `internal/web/static/app.js`; the import page script `src/js/import.js` -> `static/import.js`) and vendors ECharts and Lucide. Edit the sources, never the bundles. Keep a Go-guarded comment as `//!` (esbuild drops other comments). After class or vendor bumps, run `make css`. Themes: curated daisyUI set on Settings → General **Appearance** (Dark / Light / Special); default follows OS (`emerald` / `dark`); override is this browser only (`localStorage` key `creatorr-theme`).

**Dev UI reload:** `CREATORR_WEB_DEV=1` (optional `CREATORR_WEB_DIR`, default `internal/web`) reloads templates and static files each request. Compose mounts `./internal/web` at `/web`. CSS still needs `make css`.

**Document title:** the browser tab is always `Creatorr`. In-page headers still use the page title.

**daisyUI first.** Stock daisyUI + Tailwind in markup, or daisy theme tokens. Prefer a different HTML pattern over custom CSS. A small glue fix (overflow, stacking, clip) belongs in `input.css` with a one-line why. Do not add another UI kit. A large or unclear fix: stop and ask.

Glue already in `input.css` (the why, not the selectors):

- Modal tips must paint outside the box, so the overlay scrolls and the box does not clip. Modals sit above the shell navbar. Tall tip-less previews (`.modal-box-scroll`) cap the box and scroll only an inner grow child; do not also scroll the overlay or the form.
- The bell menu and flash toasts sit above open modals. Toasts sit below the navbar so they do not cover the bell.
- Import list and summary tips rise above the next row on hover.
- Genre, tag, and actor rows number themselves so reorder does not need JS.
- Filter date fields stay transparent and wide enough that the browser control does not look nested.
- List-view `q_field`: uses `.select.join-item` (search icon + field select; stock daisyUI caret).
- List-view toolbar is one join: optional Multi-select + `q_field` (search icon inside the field control) + search input + Filter / Sort / View. Filter/Sort/View wrappers use `.input.join-item` (same field chrome as search; borderless triggers; no nested `btn join-item`). Menus use `dropdown-bottom dropdown-end` (open below, end-aligned) with roomy widths (Filter `w-80`, Sort `w-64`, View `w-52`). Sort shows direction on the selected option (up/down arrow); re-selecting that option toggles `dir=asc|desc` (field default when omitted). An open Filter/Sort/View menu stacks above later list toolbars on the same page (series-detail Sources over Videos); hovered tips stay above menus. Hidden explorer `type`/`at` (and scope) fields sit before the first `.join-item`; `input.css` rounds the first `.join-item` so Multi-select keeps the join start radius.
- Validators show error only. A valid field stays neutral, including after Save on an empty optional field.
- Long format-selector tips stay one monospace line.
- A bulk-selected list row is square so the selection fill covers it. Bulk-selected cards (and gallery tiles) use an accent outline instead; image-full faces hide a background fill.
- A radio join highlights the checked choice.
- The app column is at least the `md` width so page padding does not jump; narrower viewports scroll sideways.
- Configurable list tables (`[data-list-table]`): wide tables scroll sideways in the wrap so sticky Title/Actions stay in the panel; Title (and select when shown) stick left, Actions stick right on video tables. Table chrome is one row above the wrap: Columns then dataset summary left, pager right when multi-page (so the columns menu is not clipped). Pager also sits below the wrap. Non-table paginated Explorers show the same pager above and below the rows. Column headers that match a Sort toolbar field are whole-cell HTMX links (same apply/toggle-dir URLs as Sort); active sort shows `aria-sort` and a muted up/down arrow. Toolbar Sort stays for fields with no visible column (e.g. series Date added / Last upload); no extra chip when the active sort has no column.
- Hovered daisyUI tips raise above page chrome (filter join, sticky cells, later rows); stay below the shell navbar and modals.

**List load modes** (orthogonal to View `list` | `cards` | `gallery` | `table`):

| Mode | Behavior | Size (v1) | Where |
|------|----------|-----------|--------|
| **paginated** | One page + pager (`?page=`; table: summary/columns above, pager below) | 20 | Table view on `/series`, Browser (all types), and Sources Explorer; series/video detail Files embeds (list and table) |
| **infinite** | Chunk + HTMX sentinel append; keep-depth `?through=` | 50 | Browser list views for every type (Series / Sources / Videos / Files / Queues / Notifications); `/series` list\|cards\|gallery |
| **fixed** | One shot of N; no pager, no sentinel, no `through` | 4 / 7 / 8 | Overview Recent additions (gallery, fetch 8; CSS shows 4 / 6 / 8 by breakpoint for full rows) + Most wanted (gallery, fetch 7; CSS shows 3–7 for one full row) + Recent tasks (list, 4) + series-detail Videos glance (gallery, 4 = one Browser Videos gallery row) |

**Browser list never paginated.** On `/browser`, list view is always **infinite** for every Explorer type. Table stays paginated. Do not add a paginated Browser list; use `libraryListMode(viewMode)`.

Infinite browse auto-loads up to 500 rows; a full live refresh (Want/Ignore/Delete, etc.) caps at 100 rows and scrolls the list to the top when clamped. Paginated and fixed ignore `through` if present. Bulk selection Sets survive append and capped refresh (ids past the rendered prefix stay selected in memory without checkboxes until those rows load again). Filter/Sort/View resets `through`. The infinite sentinel paints daisyUI skeleton placeholders as a loading affordance (count = min(chunk, remaining, 8)). It does not reserve height for the rest of the result set or for a full next chunk of cards, so the scrollbar cannot scrub far past loaded rows and leave pagination catching up. The scrollbar thumb will grow as each chunk appends.

## Patterns

- **Bulk confirm.** Every multi-select bar action follows one confirm policy (shared `*_BULK_CONFIRM_AFTER = 5` in each `*_bulk.js`):
  - **One-shot actions** (Monitor / Unmonitor, Want / Ignore, Refresh sidecars, Clear errors, Check integrity, Scan, Mark read / Mark unread, and any new submit-without-form bulk): confirm only when more than 5 are selected; ≤5 submit immediately. Confirm copy names the count (e.g. `Scan N sources`, `Mark read N notifications`, `Want N/M videos`).
  - **Delete** always opens a confirm modal (any selection size), including impact copy when that action has it.
  - **Edit / Edit metadata** always open their form modal (editor, not a yes/no confirm).
  New bulk actions must pick one of these three buckets. Do not invent a fourth confirm style; Ask when ambiguous.
- **Chrome.** One treatment per role. Primary is the main commit (Save, Add, verify-import). Secondary is a second add beside a primary add. Default `btn` is a labeled page-navbar action (and bulk-bar labeled actions; do not join them with icon-only actions; not outline/primary/secondary). Shared markup: `partials/btn_labeled.html` (`Icon` + `Label`; optional `Type` label|button|submit, `For`, `Disabled`, `Tip`, `Data`). An icon-only action that is not destructive uses `btn btn-square` (and modal Cancel / Keep stay plain `btn`). Soft error is a delete trigger; the confirm submit is solid error. A settings-list delete that is not joined to Edit is a ghost button with error text. Muted is for empty or inherited values and for disabled label text. Mute the text, not a tooltip or anything that wraps one (opacity fades the tip). daisyUI already fades a disabled checkbox; do not fade it again. Warning means paused or recoverable, error means failed or blocked, success means healthy or complete. Explorer selection and active list-filter chrome use accent (not primary); primary stays for commit actions (Save, Add). A disabled control does not receive hover, so put the tip on a wrapper (inside a join, `aria-disabled` on the button instead, so the seam stays one control). Tailwind class names must appear whole in templates so `make css` can see them. An icon-only control has a tooltip. A labeled button does not repeat its label in a tip.
- **Import page.** Scan and import stay available; Match can create a series. On Import, **Mark new videos as ignored** is checked and disabled. Page help says to index with that on before matching files. File matching is a collapse under the header (ordered auto-match: series uniqueid / title / folder name, then video remote id / title / series-from-folder). The toolbar starts with **Reset and rescan** (same default `btn` size as **Import**; inbox only; no folder picker or path label). The shell paints immediately, then the match catalog and one inbox scan run in parallel unless an `import` or `import_plan` task is already queued or running. Leaving the page drops those fetches with no error toast. While any of those tasks is open, the candidate list is a spinner plus a link to 'Queues', and Reset and rescan and bulk Import stay disabled until the queue drains (live; **Import now** shows the busy shell at once; the last import auto-rescans). Scanning while imports are open returns a conflict. The file list waits on the scan; Match waits on the catalog. Long scans are not cut off by the usual request timeout. Candidates are a vertical list, one item per stem group (case-insensitive; `[id]` stripped so sidecars still merge), plus sidecar-only attach groups and other non-importable files. Media under a `tvshow.nfo` tree nests in one series-folder row (`tvshow.nfo` path plus series art; those meta files are not separate candidates). Each importable row: files and match note on the left, status and Match or Unmatch on the right. Unmatch clears the pick. No series or video summary text on the row. The path is primary with a role icon (truncates with ellipsis when tight); extra sidecars stay visible as a count plus role icons (basename tips). Short status on the right of that file line: Matched, New, unmatched, or block reason (duplicate episode claim / duplicate create remote id). tvshow.nfo folder rows use the same path line layout (path truncates before sidecar count/icons move) with Matched or unmatched on the right. Scan auto-match text does not include the remote id. An empty scan is an alert. No scan status line and no incomplete-full-scan warning on this page. A divider sits above the toolbar: **Reset and rescan** (default `btn` size, clears every pick then scans again), **Show only unmatched** (warning and error rows: unmatched, duplicate episode claim, duplicate create remote id; success rows hidden), and **Import** on the right (wraps when tight; label `Import (matched/total)` for media; no animation). Load and **Reset and rescan** scan the import folder; Reset and rescan clears matches (daisyUI confirm modal when the operator has manual picks). **Reset and rescan** toasts how many auto matches were found; the first load stays quiet. The candidate list is a nested inbox tree rooted at the import path (label `/import/`), drawn as a flat list with a continuous CSS left rail for depth. Every directory row shows the path segment relative to its parent (root keeps `/import/`; trailing `/`; a `tvshow.nfo` tree appends `tvshow.nfo` on that path and lists series art as sidecars). Leaf file paths are relative to the parent folder row. A directory with exactly one media/sidecar group and no `tvshow.nfo` is omitted; the file line keeps that folder segment in its relative path. Every directory row (including the root) has a series join at half row width (same share as one leaf match join); picking a series auto-selects that folder and descendant folders/media, including over a descendant `tvshow.nfo` auto-select (child joins stay editable and can rematch). A `tvshow.nfo` tree auto-selects its matched or draft series on that folder and every nested folder under it; series and episode joins stay editable. Empty directories are omitted; successive dirs with no media and no `tvshow.nfo` collapse into one path row (e.g. `/import/Show/a/x/sd/`); folders stay expanded. Each importable leaf has inline searchable series and video joins sharing the row 50/50 (poster/thumb rows; episode pick list shows series title then status; join trigger is title only), series and episode filters offer Create when no match; clear is a small X inside the pick trigger when a value is selected. Series catalog loads once; episode lists fetch on open/search (capped; no full-library dump). The leading icon on the file line is the role icon (video / sidecar), not match status. Every folder and leaf row has a rounded box: neutral border for plain folders and non-importable files, warning or success fill for tvshow.nfo folder rows from the series pick, warning fill for unmatched media/sidecars, success fill when matched, error fill when two or more media rows claim the same indexed episode or two ready Create rows share a remote id. tvshow.nfo trees and folder picks auto-select series; joins stay editable. Create in a filter list applies immediately (no Add series / Add video modal); series needs a typed title; video uses the filter or suggested title and auto-fills upload date from the file when possible. Sidecar attach hides create series/video and only lists videos that already have packed media. Media lists packed videos (episode pick rows show series title then status); the episode picker hides videos already claimed by another media row, but scan can still seed the same episode on two files. Those duplicate claims stay visible in error tone until the operator clears or reassigns one. **Import** opens a summary. When any series draft exists (NFO and/or bare plus-series), steps are **Series** then **Videos**: step 1 lists editable titles plus shared root + quality (delivery/monitored defaulted); step 2 is the video tree. Confirm always posts `POST /api/import/confirm` → `import_plan`. Series and video Create are inline on Match; Series confirm still collects root and quality for drafts. Summary badges new series / new episode; warns when CREATE would use file mtime for upload date. Duplicate create remote ids disable Import. Episodes that replace packed library media are highlighted in the summary tree. When more than one ready file claims the same indexed episode, **Import** stays disabled with a tip until each video has only one media file (summary still blocks **Import now** as a safety net). When any item would override, the summary shows that the import will override already present files and requires **Override files for N episodes** before **Import now** is enabled. Footer: Cancel, optional Back/Next, primary **Import now**. Post-import integrity follows each series quality profile **File integrity** (no summary checkbox). An orphan `info.json` is listed only. A lone `.nfo` or thumb is listed only; beside a same-name video it is metadata or art. Applying an orphan or sibling updates editable metadata, then regenerates the episode NFO from the database.

- **UI labels in copy.** When hint, info, tooltip, flash, help, alert, or other operator-facing text names a page, nav item, button, control, setting, closed-set option, or status, wrap that exact label in ASCII single quotes (`'Import'`, `'Reset and rescan'`, `'Mark new videos as ignored'`, `'Settings → Queue / Domains'`). One pair around a multi-word label. Do not use bold or backticks for those labels in UI strings. Ordinary English stays unquoted. This file may still use bold for layout. Quote exact operator wording.
- **Fields.** Shared field partials: the info tip sits by the label, not joined to the control. A join may add a non-editable prefix or suffix (episode format shows the series folder and extension). Invalid fields use the daisyUI validator; the hint is hidden until invalid. On a join, the validator wraps the join so the hint still lines up. A grouped section is a fieldset with a background and border. A disabled control keeps its value in a hidden input, puts the reason tip on a wrapper, and mutes the label and hint only. A disabled checkbox mutes the label and uses the tip for why it is disabled (DisabledTitle, else Hint). A separate Hint stays muted under the control when set (purpose copy).
- **Scan schedule.** Shared cron join: field plus **enabled**. Off shows `never` and does not submit a schedule. Free-form cron and the named presets stay available. The hint under a source schedule is about upload cadence, not the Scheduler page.
- **Empty values.** List cells use ASCII `-`, or a muted word such as never, none, or default. A detail row mutes the value only and uses those words, not `-`.
